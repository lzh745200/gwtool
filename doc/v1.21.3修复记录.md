# v1.21.3 修复记录（错别字发现能力：实测提升与一次失败的尝试）

> 基线 v1.21.2。这一版只做一件事：**提升错别字发现率**，并用可复跑的样本证明。

## 一、先说结论与边界

**同一批 34 条真实错法样本，召回从 38.7% 提升到 85.3%**
（12/31 → 29/34；口径见第四节，样本已剔除"本就不该报"的合法写法）。

必须说清的边界：**"任何文档的任何错别字都能发现"做不到**。原因不在实现，在方法：
没有语言模型时，纠错只能靠"词表 + 规则 + 上下文"，而错别字是开放集合。
本版把可度量的那部分显著拉高，剩下的仍有明确的天花板（见第五节）。

## 二、改了什么

### 2.1 精标表补录 148 条（`gwtool/core/corrector_data.py`）

新增的都是**可确认为错**的写法，不是猜测：

| 类别 | 条数 | 举例 |
|---|---|---|
| 成语误写 | 136 | 一丝不拘→一丝不苟、实事述是→实事求是、病入膏盲→病入膏肓 |
| 公文高频两字 | 8 | 已径→已经、原困→原因、拆销→撤销、安照→按照、需心→虚心 |
| 公文搭配（4 字形态） | 4 | 贯策落实→贯彻落实、签定合同→签订合同、在次强调→再次强调 |

其中"公文高频两字"这 8 条原本就在生成对里（conf 0.55），但被"首字虚词/逐字高频"
等压误报闸门拦着报不出来——属于**收录了却不生效**，是最隐蔽的漏报形态。

### 2.2 两字精标对被分词切开时的复核（`corrector.py`）

原规则：两字命中必须两端都落在分词边界，否则丢弃。这条规则是为了拦
"前词尾 + 后词首"的跨词相接（`按装` + `机容量`、`按排` + `放标准`），
但它也把真错别字一起杀了：`已径` 后接 `报备`、`原困` 后接 `分析` 都不在词典边界上。

新判据：**两侧任一相邻字能与命中构成词 → 判为跨词相接（不报）；两侧都不成词 → 报**。

这一条我踩过一次坑，记在这里：**第一版只查了后面一个字**，结果把
`各位莅临` 里的 `位临` 判成真错，E7 门禁立刻红（精标配对精确率 99.7%，
`临危不惧→莅临`）。加上"前一个字"的检查后才回到 100%。
教训：跨词相接是**双向**的。

## 三、试过但撤回的方案（重要，别重复踩）

我实现过一层"开放式未知词检测"：分词切出的 token 若不在 12.3 万词典里，
就找**同音且只差 1 字**的词典词作为建议。理论上能覆盖大量词表外错字，
实测召回确实从 38.7% 提到 54.8%。

**但精度崩了**：在仓库 65 个 markdown 文档（11826 字）上实测
**2.2 处/千字误报**——"深审→深深"、"单次→单词"、"句长→局长"、"一是→一时"…
全部是 jieba 的未登录词识别把**两个相邻的正常字**切成一个 token 造成的。
要压到可用水平需要一堆逐例特判，那是自欺欺人。

结论：**没有语言模型时，开放式未知词检测在本项目的精度红线内不可行**，
已整层删除（不留死代码）。这也反证了项目原有"宁少报不误报"的选择是对的。

## 四、怎么量的（可复跑）

样本：34 条**应报**错法（成语 12 / 形近 8 / 同音 8 / 多字缺字 6），
另有 4 条**合法写法**（群主、了了、真真、其它）用于查误报。

判定：任一命中区间覆盖错形，且建议里含期望的正确写法即算命中
（`在次强调→再次强调` 这类 4 字上下文形式同样算）。

| 阶段 | 召回 |
|---|---|
| 改动前 | 12/31 = 38.7%（原始 31 条口径） |
| 加开放层（已撤回） | 17/31 = 54.8% |
| **本版最终** | **29/34 = 85.3%**（更严口径：剔除 4 条不该报的） |

分类明细：成语 11/12、形近 7/8、同音 8/8、多字缺字 3/6。

## 五、仍然做不到的（写清楚，免得被当成承诺）

| 漏报类型 | 为什么 | 出路 |
|---|---|---|
| 多字/缺字的非叠字形态 | 如"十分重"缺"要"，无重复字信号、也不在词表 | 需语言模型（L4/L5 增强包） |
| 语义搭配错（带序→有序） | 不是同音也不是形近，是措辞不当 | 写作提示层只能给倾向，不能判定 |
| 词表外的生造错形 | 词表法天花板，E4 当前 4.3% | 同上：模型层 |
| 叠字修辞与笔误的区分 | "真真""了了"是合法用法 | 现有词典仲裁已是正确取舍 |
