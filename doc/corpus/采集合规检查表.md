# 语料采集合规检查表

> 适用版本：v1.12.0+
> 工具：`scripts/fetch_corpus.py`（开发期本地运行，**不进产品运行时**）
> 关联文档：`doc/corpus/README.md`（语料契约）、`doc/corpus/AUTHORIZATION.example.json`

本检查表用于"从站点采集 / 从其它系统导入"真实语料时的合规自检。**逐项打勾并
签字后才能把语料放进 `doc/corpus/` 或用于 E3/E6 验收**。任何一项无法确认，
就停止采集，改用已授权语料或合成语料（合成语料只能用于 E2/E5，见契约文档）。

---

## 0. 红线（任一违反即停止）

- [ ] **只采公开可访问内容**；不绕过登录、验证码、付费墙、反爬策略。
- [ ] **逐 URL 判定 robots**；robots 禁止的页面一律跳过（并记入 `manifest.skipped`）。
- [ ] **受限站点必须有书面授权**（见 §2）；没有授权文件时工具直接拒绝（退出码 3），
      不得手工绕过。
- [ ] **不得把语料提交进 git**（`doc/corpus/*.txt`、`*.md` 语料本体不入库）。
- [ ] **不得再分发**采集内容；不得用于模型训练、产品输出、对外服务。
- [ ] **采集合规不等于脱敏完成**：PII 必须按 `doc/corpus/README.md` §3 处理，
      并用 `scripts/corpus_check.py` 复查。

## 2. 授权闸门（restricted 站点）

授权文件格式（`--authorization <json>`，模板见 `AUTHORIZATION.example.json`）：

```json
{
 "granted_by": "授权方（单位/部门 + 联系人）",
 "doc_ref": "授权文号或函件编号（不能为空）",
 "granted_at": "YYYY-MM-DD",
 "sites": ["people"],
 "scope": "用途与边界",
 "contact": "授权方联系方式"
}
```

工具判定（任一不满足 → **退出码 3**，打印缺什么）：

- [ ] 给了 `--authorization`，且是合法 JSON 对象（非法 JSON → 退出码 2）；
- [ ] 文件里的 `sites` 数组**包含**本次 `--site`；
- [ ] `doc_ref` 是**非空字符串**（授权文号/函件编号）；
- [ ] 授权范围（`scope`）覆盖"本地评测、不再分发"这一用途。

采集完成后：
- [ ] 授权文件已复制到输出目录 `_authorization.json`（留档，便于复核）；
- [ ] `manifest.json` 的 `authorization.authorization_id` 与 `sha256` 已记录。

## 3. 采集前

- [ ] 站点键选对了（`gov` / `people` / `qstheory` / `junbao` / `mod`）；
- [ ] 目标用途明确（E3 负样本？E6 增强层误报？只做抽样核查？）；
- [ ] 已阅读目标站 robots.txt 与版权/转载声明，并截图留档（存到本地，不入 git）；
- [ ] 受限站点：授权文件已取得并核对 `doc_ref`（纸质/邮件原文可追溯）；
- [ ] 先用 `--dry-run` 看计划：
      `python scripts/fetch_corpus.py --site gov --dry-run --offline`
- [ ] 站点模板不明时先探测容器：`python scripts/fetch_corpus.py --site gov --dry-run --probe`
      （会请求列表页与正文，但零写盘；看"容器命中/抽取失败"计数）
- [ ] 确认真实运行参数：`--max-docs`、`--max-pages`、`--delay`（不得低于 1.0s，
      且不得低于站点下限；people 为 120s）；
- [ ] 输出目录在**仓库外**或 `doc/corpus/`（后者默认不入 git）。

---

## 4. 采集中

- [ ] UA 可识别（默认 `gwtool-corpus-bot/1.0 ...`），不用浏览器伪装 UA；
- [ ] 每次请求间隔 ≥ 站点下限（工具内 `RateLimiter` 强制，robots 的
      `Crawl-delay` 也会被取最大值）；
- [ ] robots 禁止的页面被跳过并在控制台/清单里可见；
- [ ] 出现 403/404/429/5xx 立即停止该站采集，不重试轰炸；
- [ ] 不并发、不多线程、不翻页遍历全站（`--max-docs` 是硬上限）。

### 4.1 正文抽取质量（v1.12.0 实测教训，必读）

gov.cn 的正文页 HTML 不规范（表格嵌套/未闭合）。**实测 `lxml` 只解析出 9 个 div
就截断**，正文容器 `#UCAP-CONTENT` 随之消失 —— 于是 23 个链接全部被判"正文过短"、
0 篇入库，而日志里看不出原因。因此工具内置三道防线，采集时必须逐项确认：

- [ ] **解析器链**：优先 stdlib `html.parser`（容错好），`lxml` 仅作回退；
- [ ] **多级正文容器**：`#UCAP-CONTENT` → `.pages_content` →
      `div.trs_editor_view` → 最大文本块兜底（站点模板变化时靠它兜住）；
- [ ] **质量闸门**：正文 <200 字 或 `<p>` 段落数为 0 → 判"抽取失败"，
      写入 `manifest.failed`（**不是**静默跳过），并带上 `parser/container/
      chars/p_count` 便于定位；
- [ ] 采集前先跑模板探针：
      `python scripts/fetch_corpus.py --site gov --dry-run --probe`
      → 看"容器命中/抽取失败"计数；`候选数 > 0 但抽取成功 = 0` 即为模板失效，
      应停止采集并核对该站正文容器 id（不要靠放宽长度阈值硬凑）；
- [ ] 采集后看汇总行：`候选 / 入库（平均字数）/ 抽取失败 / 跳过`；
      `抽取失败` 非 0 时必须逐条核对原因，不能当作"站点没有正文"。

## 5. 采集后

- [ ] `manifest.json` 存在，且每篇都有：`source_url` / `site` / `title` /
      `fetched_at` / `chars` / `sha256` / `authorization_id` /
      `license_note` / `robots_allowed`；
- [ ] `skipped` 列表已复核（robots 禁止/正文过短/抓取失败三类原因合理）；
- [ ] `failed` 列表为空，或每条"抽取失败"都已解释（正文过短/无 `<p>` 段落/
      容器未命中）；`stats.container_hits` 与站点模板一致；
- [ ] 正文是**纯文本**（无 HTML 标签、无 script/style 残留、无导航噪声）；
- [ ] PII 体检通过：`python scripts/corpus_check.py <输出目录> --out <报告>`
      → 退出码 0；
- [ ] 人名/单位名/文号等已按契约人工脱敏（工具不猜人名）；
- [ ] 语料总量达到验收门槛（建议 ≥2 万字；见 `doc/corpus/README.md`）；
- [ ] 语料指纹已记录：用 `eval_corrector.py --corpus-manifest` 留档。

---

## 6. 退出码对照

| 码 | 含义 | 处理 |
|---|---|---|
| 0 | 成功（含 dry-run、导入完成） | 继续走 §5 |
| 1 | 运行期失败（网络不可用、robots 无法确认、列表页抓不到、`--from-dir` 无文件） | 排查网络/参数；**不要**为了提高成功率降低限速或扩大批量 |
| 2 | 用法错误（参数非法、授权文件不是合法 JSON、`--delay` < 1.0） | 按提示改参数 |
| 3 | 授权不足（受限站点缺授权 / `sites` 不含该站 / `doc_ref` 为空） | 走 §2，拿书面授权 |

## 7. B 路线：从数据库 / 手工导出导入

- [ ] 导出源可追溯（哪个系统、哪次导出、导出了多少篇）；
- [ ] 只导入 `.txt`/`.md`，UTF-8；非 UTF-8 会被跳过并记录；
- [ ] 若来源是受限站点内容，**同样需要授权文件**（工具对 `--from-dir` 一视同仁）；
- [ ] 命令：
      `python scripts/fetch_corpus.py --site gov --from-dir D:/导出语料 --out corpus_out`
- [ ] 导入后同样走 §5（manifest / 脱敏体检 / 指纹）。
