# 真实语料契约（E3 / E6 负样本）

> 适用版本：v1.11.0+
> 相关脚本：`scripts/corpus_check.py`（语料体检）、`scripts/eval_corrector.py`（评测门禁）
> 相关文档：`doc/纠错系统落地方案.md`、`doc/_audit_v19/02_correction.md`

本文把"拿真实公文当负样本"从口头约定变成**可执行契约**：语料放哪、怎么脱敏、
怎么体检、评测怎么跑、哪些数字才算达标。不满足契约时，评测脚本会显式
`SKIP` 或 `FAIL`，不会给出"看起来全绿"的假结论。

---

## 1. 为什么必须用真实公文语料

`eval_corrector.py` 内置的 `DEFAULT_NEG` 只有 8 句 / 224 汉字，**只用于示意**：
1 处命中就是 44.6 处/万字，0 处命中时 95% 置信上界也有约 134 处/万字——统计上
没有意义。所以：

- **不传 `--corpus` 时**，E3/E5/E6 一律标「示意·不参与门禁」并记为 `SKIP`，
  不影响退出码；
- **传了 `--corpus` 且语料有效时**，E3/E5/E6 才真正参与门禁（FAIL 会 exit 1）；
- CI 只跑 `--profile base`（E1/E2 硬门禁 + E3/E5 示意），**不替代**本契约。
  发布前必须由负责人按本文在真实语料上跑一遍。

### 为什么不能拿技术文档当负样本

`doc/*.md` 这类技术文档（设计稿、审查报告、方案说明）**不是公文**：里面混排
Markdown、代码片段、英文缩写、表格线、路径与版本号。实测在 v1.9/v1.10 的引擎上
用它跑 E3 是 **129 处/万字**，命中集中在「标点规范 / 生成层同音对」这类
**技术文档特有的写法**上。那不是"公文写错了"，而是口径不对：

- 用它调规则，会把"正常技术文档"当成误报来源，规则被迫放宽 → 真实公文误报上升；
- 用它验收，E3 永远是红的，门禁失去意义；
- 真正的公文负样本应当**没有错别字、没有格式硬伤**（或已知错点已标注）。

同理，小说、新闻、聊天记录、OCR 未校对稿都不能直接混入。

## 2. 语料放置约定

| 项 | 约定 |
|---|---|
| 位置 | ①仓库内 `doc/corpus/`（**默认不入 git**，只提交本 README）；②外部目录（如 `D:/公文语料`、`/srv/gwtool-corpus`） |
| 格式 | `.md` 或 `.txt`，**UTF-8**（可带 BOM）；其它编码先转存 |
| 组织 | 一文件一篇公文；`eval_corrector.py --corpus <目录>` 只扫**目录第一层**；`corpus_check.py` 会**递归**体检子目录（防止有人把未脱敏文件塞进子目录绕过检查） |
| 规模 | 建议 **≥20 篇、≥2 万汉字**；硬下限见下（单篇 ≥100 汉字、全量 ≥1000 汉字） |
| 命名 | `单位_年度_文种.md`（单位名用代号，如 `A局_2026_通知.md`）；禁止把真实人名/单位名写进文件名 |
| 说明文件 | 本 README 会被 `corpus_check.py` 与 `eval_corrector.py` **自动跳过**，不会当成负样本；其它说明文档请勿放进该目录（或以 `--corpus` 指向子目录规避） |
| 版本 | 语料一旦用于某次验收就不要在验收中途改动；改了就换 `--corpus-manifest` 文件重新对比 |

> 维护者注意：仓库根 `.gitignore` 应包含
> `/doc/corpus/*` 与 `!/doc/corpus/README.md`，确保语料本体永不入库。
> 若 `.gitignore` 尚未包含，请在提交前手工确认 `git status` 里没有语料文件。

## 3. 脱敏规范（硬性要求）

**凡是能从语料还原到具体自然人的信息，一律先脱敏再放进来。**

### 3.1 工具会判 FAIL 的（正则可确定）

| 类型 | 例子 | 处理 |
|---|---|---|
| 身份证（18 位） | `110101199003072316` | 删除或替换为 `××××××××××××××××××` |
| 手机号 | `13812345678` | 替换为 `1××××××××××` |
| 邮箱 | `zhangsan@example.com` | 删除或替换 |
| 银行卡 | 16/19 位连续数字 | 删除或替换 |
| 座机号 | `010-12345678`、`057188888888` | 替换为 `0×××-××××××××` |

命中任意一条，`corpus_check.py` **退出码 1**，并在报告里给出 `文件:行`；
报告本身只输出**掩码值**（如 `11**************16`），不会二次泄露。

### 3.2 工具**不猜**、必须人工脱敏的

- **人名**：统一替换为「张三/李某/某同志」。工具不做姓名识别——中文姓名没有
  可靠正则判据，靠启发式猜会把"没报错"误当成"已脱敏"，比不查更危险。
- **具体单位名 / 内部机构名**：替换为「A局/B县/C单位」或 `××市教育局` 占位写法
  （`××` 是公文书里的规范占位，引擎也认这种写法）。
- **文号、案号、合同号、金额、地址、账号**：保留位数形式、替换具体值。
- **涉密/内部材料**：先确认材料密级与可外流范围；工具只能对
  「内部资料/机密/绝密」等**标记词**给 warning，不能替你判断密级。

### 3.3 最小化

只保留评测需要的正文段落（通常每篇 1~3 段即可），不要把整卷（含附件、签字页、
联系方式）搬进语料目录。

## 4. 语料体检

```bash
# 体检（递归 .md/.txt）：编码、空文件、单篇下限、总量下限、PII
.venv/Scripts/python.exe scripts/corpus_check.py doc/corpus

# 落盘 JSON + Markdown 报告（--out 不带扩展名时同时写 .json/.md）
.venv/Scripts/python.exe scripts/corpus_check.py doc/corpus --out artifacts/corpus_report

# 只写一种格式
.venv/Scripts/python.exe scripts/corpus_check.py doc/corpus --out artifacts/corpus_report.json

# 调整下限（默认单篇 100 汉字 / 全量 1000 汉字）
.venv/Scripts/python.exe scripts/corpus_check.py doc/corpus --min-doc-cjk 300 --min-total-cjk 20000
```

退出码：

| 码 | 含义 |
|---|---|
| 0 | 语料合格（可能含 warning，不影响退出码） |
| 1 | 有问题：非 UTF-8 / 空文件 / 单篇过短 / 总量不足 / 命中 PII / 目录里没有 `.md`、`.txt` |
| 2 | 用法错误：路径不存在、单文件后缀不是 `.md`/`.txt`、参数非法 |

报告包含：结论与规模、问题清单（`文件:行` + 掩码命中）、warning 清单、
逐文件 sha256 与汉字数——sha256 可直接用于和 `--corpus-manifest` 对照。

## 5. 评测命令与阈值

### 5.1 基础门禁（任何机器，无需增强包）

```bash
.venv/Scripts/python.exe scripts/eval_corrector.py \
    --profile base --corpus doc/corpus \
    --json artifacts/eval_base.json
```

- E3/E5 参与门禁；E1/E2 照常硬门禁；E4/E6 因 profile 不含增强层 → SKIP。
- 退出码 0 才算通过。

### 5.2 增强包验收（已装 L4/L5 的机器）

```bash
.venv/Scripts/python.exe scripts/eval_corrector.py \
    --profile all --require-packs --corpus doc/corpus \
    --corpus-manifest artifacts/corpus_manifest_before.json \
    --json artifacts/eval_all.json
```

- `--require-packs`：**E4/E6 必须真实运行**。未装增强包、onnxruntime 缺失、
  或没给真实语料 → E4/E6 判 **FAIL**（不再 SKIP），防止"装了包但根本没测到"。
- `--corpus-manifest`：写逐文件 sha256 + 聚合 sha256 + 样本量。改前/改后各存一份：

  ```bash
  # 两次评测后先比清单，再比数字
  python - <<'PY'
  import json
  a = json.load(open("artifacts/corpus_manifest_before.json", encoding="utf-8"))
  b = json.load(open("artifacts/corpus_manifest_after.json", encoding="utf-8"))
  print("聚合 sha256 一致", a["corpus"]["aggregate_sha256"] == b["corpus"]["aggregate_sha256"])
  print("样本量", a["corpus"]["chars"], "->", b["corpus"]["chars"])
  PY
  ```

  清单不一致时，指标变化不可归因到引擎改动，验收无效。

### 5.3 阈值（与脚本内的 `TH_*` 常量一致）

| 项 | 含义 | 阈值 | 说明 |
|---|---|---|---|
| E1 | 人工精标集检出率 | **= 100%** | 精标对必须全部认出 |
| E2 | 生成对上下文召回 | **≥ 75%** | 用内置/合成数据，不依赖语料；发布口径建议 ≥80% |
| E3 | 真实公文负样本误报 | **≤ 0.5 处/万字** | 只看真实语料；技术文档口径无效（见 §1） |
| E4 | 词表外错字召回 | ≥ 5% | 仅增强包机器可门禁；未装包时 SKIP |
| E5 | 基础三层耗时 | **≤ 100 ms/千字** | 取语料前 40 段做探针 |
| E6 | 开启增强层后新增误报 | **≤ 1.0 处/千字** | 仅增强包机器；必须给真实语料 |

## 6. 口径边界（容易踩的坑）

1. **E3 的分母是真实语料**：语料 <1000 汉字会被 `corpus_check.py` 直接判 FAIL；
   建议 ≥2 万字，否则 1~2 处误报就让指标剧烈跳动。
2. **E5 取语料前 40 段**：段落过短时，每段固定开销会被放大成
   "几百 ms/千字"的假超标。语料段落建议 ≥30 汉字/段（真实公文自然满足）。
3. **E1/E2 与语料无关**：它们跑内置精标对与种子库生成对，用来盯"词表/召回"；
   不要用真实语料去调 E1/E2 的数字。
4. **E6 必须有真实语料**：增强层误报率的分母是真实公文汉字数；只有增强包、
   没有语料时，即使 `--require-packs` 也判 FAIL（见 §5.2）。
5. **合成语料的边界**：仓库提供的合成语料生成器（如 `scripts/gen_corpus.py`）
   用模板+句式库拼装、带「合成」标注，**只能用于 E2 召回压测 / E5 吞吐压测 /
   跨平台确定性 smoke**；它**不能**用于 E3/E6 —— 合成文本天生没有真实公文的
   行文习惯，用它算误报率等于自己出题自己考。E3/E6 的负样本必须是真实公文。
6. **语料只增不改**：一次验收期间改语料 = 换了考卷。确需更换，保留两份
   manifest 并在验收记录里说明。
7. **`doc/*.md` 不是语料**：技术文档、审计报告、本 README 都不要复制进
   `doc/corpus/`。

## 7. 验收清单（复制到发布记录里逐项打勾）

- [ ] `corpus_check.py` 退出码 0；报告已归档（JSON+MD）
- [ ] `--profile base --corpus ...` 退出码 0（E1=100%、E2≥75%、E3≤0.5/万字、E5≤100ms/千字）
- [ ] 有增强包的机器：`--profile all --require-packs --corpus ...` 退出码 0
      （E4≥5%、E6≤1.0 处/千字，且两行均为 `[PASS]` 而非 `[SKIP]`）
- [ ] `--corpus-manifest` 已归档；与上次验收的语料聚合 sha256 一致（或已说明差异）
- [ ] 语料本体未进入 git（`git status` 无 `doc/corpus/*.md`、`*.txt`）
