## 二、本批的取舍（写清楚，避免"为达标而达标"）

1. **段落索引 40% 验收线**：同一正文客观上存在 4 份副本（`documents` / `documents_fts_content` / `paragraphs` / `paragraphs_fts_content`），在不破坏"索引可缺失、现场派生兜底"设计的前提下，**相对增量 40% 结构上不可达**。本批给出可执行策略（阈值/关闭 + 维护清理）并修正了度量口径，同时建议验收补充"绝对预算"（实测索引 ≈2.4KB/篇）。
2. **`.doc` 走纯 Python**：审计实测 COM 只用于"取纯文本"（结构信息本就丢弃），纯 Python 结果等价且快 ~2400×。为避免极端文件质量下降，保留"可疑才重试 Office"的兜底，而不是简单粗暴地一刀切。
3. **法定文种不出"更像"提示**：法定文种间相似度判定的样本仍是自撰示意（`n=0`），精度无保证，故选择"只识别、不比较"；7 种无模板文体的提示精度不变。
4. **发文字号不加 UNIQUE 索引**：历史库可能有重复，迁移会失败；`BEGIN IMMEDIATE` + 事务内查重已覆盖同进程多线程/多进程写者（并发用例证明），UNIQUE 索引留待有真实迁移需求的版本。

## 三、本批明确未做（留到 C 批/按需）

- 真实公文语料库（50–100 篇脱敏）：E3/E6 从"示意"升级为门禁的前置条件；
- ARM64/麒麟真机性能与渲染验收（本批全部数字来自 Windows x64 本机）；
- 内置 PDF 渲染器的表格/分栏细节、PDF 解析的表格结构还原；
- 资料库"轻量行查询 DAO"（把 29.5ms 里 28ms 的固有取数再压一档）；
- `test_import_probe` 的 COM 反初始化消噪（环境噪声，非回归）。
