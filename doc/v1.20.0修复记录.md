# v1.20.0 修复记录（P2 可选 ONNX 增强包 + P3 独立病句基准）

> 基线 v1.19.0。P2 的目标不是"再训一个大模型"，而是让**现成可选 ONNX 包**
> 真正可用、可测、可控；P3 的目标是引入**不归我们编写**的病句基准，检验规则层
> 在真实分布上的水平。结论不粉饰：P2 修好并达标，P3 基线偏低（见 §三）。

## 一、P2：可选 ONNX 增强包（L4 拼写层）

### 1.1 定位到的三个真实缺陷

1. **词表被 `splitlines()` 切错**
   `csc_neural._load_engine` 用 `str.splitlines()` 读 `vocab.txt`。BERT 词表里
   有作为 token 一部分的 U+2028/U+2029 等 Unicode 行分隔符，`splitlines()`
   会额外切行。MacBERT 词表实测被多切 **2 行**，整表 token→id 偏移 1~2：
   干净句"会议在北京召开"被改成"伟议筑北京喆四"。
   → 改为只按 `"\n"` 切、仅去行尾 `\r`（`_parse_vocab`）。

2. **输出与输入错位（CLS/SEP 约定不一致）**
   该导出要求**调用方**补 `[CLS]/[SEP]`，而旧代码按"图内已补"处理，等于把
   整句预测左移一位。→ 新增加载期探针：用干净短句分别测"裸字序列"与
   "CLS+字+SEP"的一致率，自动选择；解码按输出比输入多几行求偏移。

3. **没有有效门控**
   旧实现检测支路只看 argmax、置信度直接取检测 logits 原始值；空格、标点也会
   被"改成汉字"。真实语料新增误报 **2.43/千字**（目标 ≤1.0）。
   → 只改 CJK 汉字；检测支路 softmax 概率 ≥0.50；纠正支路 top1-top2 logit
   间隔 ≥1.0；标点不动。

### 1.2 验收（`scripts/eval_neural_pack.py`，E9）

| 指标 | 修复前 | 修复后 | 门禁 |
|---|---:|---:|---|

### 1.3 语法包（Mengzi-T5）状态

冒烟测试可加载、可推理，但在真实句上给出低质量改动（如"莫→美"），且
3~10 s/句。**保持实验状态、不进入验收门禁**；文档与 UI 不建议普通用户开启。
后续要可用，需要重新导出/校准该 Seq2Seq 包（tokenizer 偏移与解码策略）。

## 三、P3：独立病句基准（FCGEC）

### 3.1 数据

- 来源：FCGEC（EMNLP 2022）valid，2000 句（病句 1102 / 干净 898），
  仓库 `xlxwalex/FCGEC`（Apache-2.0）；
- **不随仓库分发**：`scripts/fetch_fcgec.py` 走 GitHub contents API + 固定
  sha256（`6afb961c…`）拉到 `doc/bench/`（已 gitignore）。

### 3.2 实测（语法层 v2，不含拼写/神经层）

| 指标 | 结果 |
|---|---:|
| 句级召回（任一语法命中） | **32/1102 = 2.9%** |
| 定位召回（命中与标注 pos ±2 重叠） | **3/1102 = 0.3%** |
| 干净句自动误报 | 2 处 / 44,251 字 = **0.452/万字** |
| 仅提示命中 | 5 处 |

按类型：SC 17/220、CM 9/222、CR 4/61、IWC 1/249、IWO 0/192、
ILL 1/117、AM 0/41。

### 3.3 结论（不粉饰）

- 自建病句集 93.3% vs 独立集 2.9%：**说明 v1.19 的高召回主要来自"规则与
  自建样本同源"**，不能当作真实分布能力；
- 语法层仍只适合"高精度窄覆盖"（干净句误报 0.45/万字，尚可），
  但召回远不够；下一步应按 FCGEC train 做**数据驱动规则挖掘**并重新评测，
  而不是继续手写；
- P3 交付的是**可复现基准与诚实基线**，不是"已经达标"。
