# v1.21.0 修复记录（麒麟稳定性 / 中文输入法 / 任意素材导入）

> 现场反馈三个问题：① 麒麟安装后闪退、不稳定；② 无法切换输入法、打不出中文；
> ③ 写作参考素材库导不进"一般任意文档"。本版逐项处理，并把无法在本机复现的
> 问题改成**可现场取证 + CI 门禁可拦截**的形态。

## 一、麒麟安装/启动稳定性

### 1.1 先让闪退可诊断（此前最致命的是"没有证据"）
- `main.py` 在**导入 PySide6 之前**装 `faulthandler` + `excepthook`，启动期
  GLIBC/GLIBCXX 加载失败也会写进 `~/gwtool_启动诊断.log`（此前这些错误不进
  任何日志，桌面双击只表现为"没反应"）。
- `gwtool.sh` 把主程序的 stdout/stderr **同时落盘**（`tee -a`），退出非 0 时
  识别 `GLIBC_2.x` / `GLIBCXX_3.4.x` / Qt platform plugin / inputcontext
  四类特征，给出**对应的修复命令**并弹窗。
- 新增 `gwtool.sh --startup-report`（等价 `gwtool --startup-report`）：
  一次打印 平台/glibc/Python/PySide6+Qt 版本/QPA 与输入法环境/Qt 插件路径/
  缺库清单，现场排障不需要猜。

### 1.2 消除已知的启动期风险
- **Linux 禁用 UPX**（`gwtool.spec`）：ELF 共享库被 UPX 压缩后在麒麟上是
  已知"加载即闪退"来源；Windows 继续保留 UPX + DLL 排除名单。
- **随包分发 C++ 运行时**：CI 把构建机的 `libstdc++.so.6`、`libgcc_s.so.1`
  放进产物根目录，启动器把 `$DIR` 放在 `LD_LIBRARY_PATH` 最前；麒麟自带
  libstdc++ 偏旧时不再报 `GLIBCXX_3.4.xx not found`。
- **ABI 门禁（CI 新增）**：`scripts/check_linux_abi.py` 扫描最终产物每个
  ELF 的 `GLIBC_/GLIBCXX_` 最高版本，超过 `2.31 / 3.4.29` 直接构建失败，
  杜绝"用新系统构建、发到麒麟就闪退"的包流出去。
- deb 依赖补 `libxcb-util1`；启动器预检缺库命令同步。

> 说明：麒麟 V10 **桌面版以 glibc 2.31（Debian 11 系）为基线**；更老的
> 麒麟（glibc 2.28）没有可用的 PySide6 aarch64 轮子，程序会通过
> `--startup-report` 明确报出 glibc 不匹配，而不是静默闪退。

## 二、中文输入法（Qt6 + fcitx5/ibus）

Qt6 不再走 XIM；打包版只加载包内 `platforminputcontexts`，系统装的
fcitx5-qt6/ibus 插件默认找不到，于是"窗口能开、切不了中文"。

- 新增 `gwtool/ui/ime.py`，在 `QApplication` **之前**：
  1. 探测包内/系统的 compose / ibus / fcitx5 插件；
  2. 尊重用户已设的 `QT_IM_MODULE`，未设置时按 `XMODIFIERS`/`GTK_IM_MODULE`
     自动选择；
  3. 把系统 Qt6 插件目录追加进 `QT_PLUGIN_PATH`（不覆盖包内路径）；
  4. 探测到会话使用 fcitx/ibus 但插件缺失时，启动后弹一次可操作提示
     （`sudo apt install fcitx5-frontend-qt6` 或 `ibus`）。
- `gwtool.spec` 显式收集 `PySide6/plugins/platforminputcontexts/*`，
  打包版自带 compose/ibus 插件。
- deb 增加 `Recommends: fcitx5-frontend-qt6 | fcitx-frontend-qt6, ibus`。
- `gwtool.sh` 同步做环境兜底（未设置时导出 `QT_IM_MODULE`、追加系统插件目录）。

> 边界：只装 fcitx4（无 Qt6 前端）的系统仍无法输入中文，程序会明确提示安装
> `fcitx5-frontend-qt6` 或 `ibus`；这是 Qt6 生态限制，不是本程序可以绕过的。

## 三、任意素材文字导入写作参考库

此前「写作参考库」只认外部构建的固定语料包（index.json + annotations/），
用户自己的通知/总结/讲话稿/PDF 都进不去。

- 新增 `gwtool/core/material_import.py`：把**任意文档或任意文字**转成同一种
  只读语料包，`MaterialPack` 与检索/预览/插入零改动即可用。
  - 文件走 `importer.parse_any`（docx/doc/wps/txt/rtf/pdf/md/html，
    扫描件走内置 OCR，图片走 OCR）；解析失败再按 UTF-8/GB18030/UTF-16
    纯文本兜底——**扩展名不认识也尽量入库**；
  - 粘贴文字直接入库；
  - 逐句切分 + 角色启发式（论点/论据/过渡/结尾/其他）；
  - 内容 sha256 去重、标题重名自动加序号、原子写入、单篇防爆上限。
- 对话框新增**「导入素材…」（可多选/拖入文件夹）、「粘贴文字…」、拖拽文件**
  三种入口；导入后自动切到「我的素材」并可直接检索/插入。
- 自建素材存 `<数据目录>/material_packs/我的素材/`，与公版语料包互不影响，
  随"备份/恢复"一起迁移。
