# 麒麟 ARM64 / Windows 真机验收指南

> 适用版本：v1.10.0（C 批，跨平台验收前置件）
> 验收对象：麒麟 V10 SP1 ARM64（Debian 11 系，glibc 2.31）为主；Windows x64 为参照基线。
> 特性：零网络、零新增依赖、不触碰真实用户库（功能 smoke 全部在临时目录 + 临时库内完成）。

本指南配套脚本：`scripts/accept_env.py`。它把「环境采集 + 功能 smoke + 判据」变成一条命令，
输出可回传的 `accept_report_<时间戳>.json`（机器判据）与同名 `.md`（人读摘要）。

---

## 1. 这台机器要验什么

| 类别 | 验什么 | 为什么要真机 |
|---|---|---|
| 环境 | OS/发行版/架构、Python 版本、PySide6/PyMuPDF/jieba/python-docx 版本、中文字体、屏幕与 DPI、种子库 | 字体与 Qt 平台插件是最常见的「Windows 能跑、麒麟白屏」来源 |
| 建库 | `init_schema`（SCHEMA_VERSION=7）、16 业务表 + 4 FTS5 | 老库迁移/系统 SQLite 版本差异只会真机暴露 |
| 导入 | txt / Markdown → DocTree → 入库 | 解析链路依赖系统编码与可选库 |
| DOCX | 内置 `docxgen` 生成、python-docx 可回读 | 只验结构，不要求装 Office/WPS（**不依赖 COM**） |
| PDF | 内置 Qt 渲染 `render_compiled_pdf`，PyMuPDF 量页数与**正文行距** | 行距由 Qt 块级 FixedHeight 实现，ARM64 Qt 行为必须实测 |
| 备份/恢复 | 自洽快照 → zip → 恢复，文档数回到备份时点 | 灾难恢复是数据安全底线 |
| 性能 | 纠错 1 万字、写作提示 1 万字耗时 | ARM64 与 Windows 的 CPU/分词性能差异大 |

判据与阈值见第 6 节；报告里的 `S`/`WARN` 明细会直接指出哪一项偏离。

---

## 2. 安装 .deb（推荐路径）

产物：`gwtool_<版本>_linux_arm64.deb`（CI 组装；载荷为 PyInstaller onedir，安装到 `/opt/gwtool`）。

```bash
# 0）确认架构（必须是 aarch64；x86_64 机器请换 x64 包）
uname -m
# 输出 aarch64 才继续

# 1）安装（含依赖；离线机器请先准备同版本 deb 依赖）
sudo dpkg -i gwtool_1.10.0_linux_arm64.deb
sudo apt-get -f install          # 若提示缺依赖
```

安装后：

- 图形入口：开始菜单「公文汇编助手」；命令行：`/opt/gwtool/gwtool.sh`
- 数据目录：`~/.local/share/gwtool/`（库、备份、附件、日志都在这里，升级前请备份）
- 启动失败日志：`~/gwtool_启动诊断.log`

先做一次「产物自检」（不启动 GUI）：

```bash
/opt/gwtool/gwtool.sh --runtime-report
```

应看到：`frozen: True`、平台/架构、Python 与关键依赖版本、L4/L5 依赖是否就绪。
把这段输出与验收报告一起回传。

> `.run` 自解压包（`gwtool_kylin_aarch64.run`）安装位置是 `~/.local/opt/gwtool`，
> 命令行为 `~/.local/opt/gwtool/gwtool.sh`，其余步骤相同。

### 2.1 只拿到 deb、没有源码时

deb 内只有冻结后的程序，**不包含** `scripts/accept_env.py`（脚本要读源码树与 Python 依赖）。
此时：

1. 用 `gwtool.sh --runtime-report` + 手工冒烟（导入一份 docx、一键汇编、导出 PDF、备份恢复）填环境报告；
2. 若需完整自动验收，向构建方索取源码目录 + `wheels_aarch64/`，按第 3 节在**同一台麒麟机**上跑脚本。

## 3. 跑自动验收脚本（源码 + venv）

要求：Python 3.9+、`python3-venv`；离线依赖来自 `wheels_aarch64/`（与 `build_kylin_arm64.sh` 同源）。

```bash
# 1）准备运行环境（首次）
cd ~/gwtool_src
python3 -m venv .venv
source .venv/bin/activate
pip install --no-index --find-links wheels_aarch64 -r requirements.txt

# 2）快速自检（跳过耗时项，约秒级；建议先跑这个）
python scripts/accept_env.py --fast --out ~/验收报告

# 3）完整验收（含纠错/写作提示计时）
python scripts/accept_env.py --out ~/验收报告

# 4）只看 JSON（便于脚本/CI 采集，不写文件）
python scripts/accept_env.py --fast --json
```

说明：

- 脚本自动把功能 smoke 放在临时目录与临时 SQLite 库里（退出时清理），**不会打开或修改**
  `~/.local/share/gwtool/gwtool.db`。
- SSH 无图形会话时脚本自动切 `QT_QPA_PLATFORM=offscreen`，`env.screen` 会标 WARN；
  PDF 仍可渲染与量行距（Qt 离屏）。
- 报告默认写到产品数据目录（`~/.local/share/gwtool/`），建议用 `--out` 指到单独目录，
  避免与用户数据混放。
- 退出码：`0` = 没有 FAIL（WARN/SKIP 允许）；`1` = 有 FAIL；`2` = 脚本自身无法启动
  （参数/输出目录不可写等）。环境能力缺失（缺中文字体、无屏幕等）只标 WARN。

## 4. 回传清单

把以下内容打包回传（单个 zip 即可）：

1. `accept_report_<时间戳>.json` 与 `.md`（两个都要）；
2. `/opt/gwtool/gwtool.sh --runtime-report` 的输出文本；
3. `uname -a`、`cat /etc/os-release`、`python3 -V`（或 `.venv/bin/python -V`）；
4. `dpkg -l | grep gwtool` 与安装包文件名；
5. 若有 FAIL/WARN：对应系统日志（`~/gwtool_启动诊断.log`、`~/.local/share/gwtool/logs/`）。

报告本身**不含真实公文正文**：功能 smoke 只用内置样例，环境信息里只有版本、字体名、
屏幕尺寸和路径。

## 5. Windows x64 验收（参照基线）

```powershell
.\.venv\Scripts\python.exe scripts\accept_env.py --fast --out .\验收报告
.\.venv\Scripts\python.exe scripts\accept_env.py --out .\验收报告
```

Windows 环境应额外检查：中文字体（宋体/仿宋/微软雅黑）、`devicePixelRatio`
（150% 缩放应为 1.5）、PDF 行距与 ARM64 是否一致。B 批全部性能数字来自
Windows x64，可作为 ARM64 的对照基线。

## 6. 判据表

脚本把每项检查写成 `checks[]`，状态含义：**PASS** 达标；**WARN** 环境/能力缺失
（不阻断，但需在回传说明里解释）；**FAIL** 不达标（阻断验收）；**SKIP** 本次模式跳过。

| 检查 id | 判据 | PASS 条件 | 备注 |
|---|---|---|---|
| `env.python` | Python 版本 | ≥ 3.9 | 低于 3.9 WARN（本项目目标版本） |
| `env.qt` | PySide6/Qt | 已安装且可创建 QGuiApplication | 缺失 WARN |
| `env.pymupdf` | PyMuPDF | 已安装 | 缺失 WARN（PDF 检查会跳过） |
| `env.jieba` | 中文分词 | 已安装 | 缺失 WARN（纠错会退化） |
| `env.fonts` | 中文字体 | 系统有 CJK 字体，或 PyMuPDF `Droid Sans Fallback` 注入成功 | 全无则 WARN，PDF 中文可能空白 |
| `env.screen` | 屏幕/DPI | 能取到 primaryScreen 且非离屏会话 | SSH/离屏环境 WARN（PDF 仍可离屏渲染） |
| `env.seed_db` | 种子库 | `gwtool/resources/data/seed.db` 存在 | 缺失 WARN（词库/种子数据不完整） |
| `smoke.db` | 建库/迁移 | `documents` 表存在，`user_version=7` | 旧库升级路径由既有测试覆盖 |
| `smoke.import` | 导入 txt/md | 2/2 解析成功且入库 2 篇 | 失败 FAIL |
| `smoke.docx` | 生成 DOCX | 文件 >3 KB、python-docx 可读、含样张正文 | 不依赖 Office/WPS |
| `smoke.pdf` | PDF 页数与行距 | 页数 ≥ 2；正文行距 **28 ± 1.5 pt**；中文字符 > 0 | 行距取正文页相邻行基线中位数；中文字符为 0 记 WARN（字体未生效） |
| `smoke.backup_restore` | 备份/恢复 | 恢复成功；恢复后文档数 = 备份时点数；恢复前新增文档被回退 | 失败 FAIL |
| `perf.corrector` | 纠错 1 万字 | ≤ **2000 ms** 且命中 > 0 | `--fast` 时 SKIP |
| `perf.writing_hints` | 写作提示 1 万字 | ≤ **3000 ms** 且提示 > 0 | `--fast` 时 SKIP |

判定：`summary.fail == 0` 即验收通过（WARN 需说明）。`verdict` 为 PASS/WARN/FAIL。

## 7. 已知平台差异（正常现象，不要当缺陷）

1. **字体族回退**：Windows 用宋体/仿宋/微软雅黑；麒麟常见 Noto Sans CJK / 思源 /
   文泉驿，精简系统可能一个都没有。此时 `pdfrender.ensure_cjk_font()` 会从 PyMuPDF
   注入 Droid Sans Fallback 兜底，报告 `env.fonts` 会显示 `fallback=Droid Sans Fallback`。
   这是**预期降级**，不是失败；但字体族差异会让 PDF 字形/字宽与 Windows 略有不同。
2. **DOCX 字体名**：docx 里记录的是模板字体名（仿宋_GB2312 等）。麒麟上缺该字体时，
   本机打开会回退；文件拿到 Windows/WPS 上仍按字体名替换。验收只看结构，不看字形。
3. **Qt 渲染差异**：Qt 版本、字体度量与分页算法在不同平台会带来 ±1 页的分页差异；
   行距判据 28±1.5pt 与页数 ≥2 已覆盖这种差异。不要用「逐像素一致」做判据。
4. **DPI / 缩放**：麒麟桌面 150% 缩放时 `device_pixel_ratio` 可能为 1.5 或 2.0；
   报告有记录即可。脚本本身不依赖缩放比例做判定。
5. **性能**：ARM64 通常比 Windows x64 慢；阈值已放宽到 2 s / 3 s。
   冷启动首次调用包含 jieba/风格语料懒加载，报告是单次冷测；若接近阈值，
   可在同一机器上再跑一遍 `--json` 对照（热态）。
6. **无 Office/COM**：验收脚本不调用 Word/WPS/LibreOffice，也不 import
   `win32com`/`pythoncom`，因此可以在最小安装的麒麟上运行。

## 8. 常见问题

| 现象 | 处理 |
|---|---|
| 启动报 `Could not load the Qt platform plugin "xcb"` | 按 `gwtool.sh` 提示补装 `libxcb-cursor0 libxcb-icccm4 libxkbcommon-x11-0 libgl1 libegl1` 等 |
| 脚本报 `报告目录不可写`（退出码 2） | `--out` 指到可写目录，如 `~/验收报告` |
| `env.screen` WARN | SSH/无显示会话运行；如需真实屏幕数据，在桌面终端重新执行 |
| `env.fonts` WARN 且 PDF 中文字符 0 | 安装 `fonts-noto-cjk` 或确认 PyMuPDF 版本 ≥1.24；否则正文会空白 |
| `smoke.pdf` 行距 FAIL | 优先检查 `pdfrender._apply_fixed_line_height` 是否在该机上被 Qt 版本差异影响；附报告与 `--runtime-report` 回传 |
| 性能项 FAIL 但机器较老 | 复跑一次排除冷启动；仍 FAIL 则记录 CPU 型号与耗时，附报告回传 |

## 9. 回滚

### 9.1 卸载 deb / .run

```bash
# deb 安装
sudo dpkg -r gwtool

# .run 安装
rm -rf ~/.local/opt/gwtool
rm -f ~/.local/share/applications/gwtool.desktop

# 桌面数据库（可选）
command -v update-desktop-database >/dev/null && update-desktop-database ~/.local/share/applications
```

卸载**不会**删除 `~/.local/share/gwtool/` 里的用户数据与备份。

### 9.2 升级/验收前的数据保护

```bash
cp -a ~/.local/share/gwtool "$HOME/gwtool_data_backup_$(date +%Y%m%d_%H%M)"
```

恢复：把备份目录换回 `~/.local/share/gwtool`（先关程序），或在程序内用
「备份/恢复」从 zip 还原；程序启动时对老库会先做 `*_premigrate_v*.zip` 自动留档。

### 9.3 回退到上一版程序

保留旧版 deb / `.run` 安装包；卸载当前版后安装旧版即可。**不要**手工改
`PRAGMA user_version`——库由更新版本程序创建时，旧版会明确拒绝打开并保留原件，
这是有意的数据保护行为。
