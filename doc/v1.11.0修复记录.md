# v1.11.0 修复记录（C 批：语料基准、跨平台验收、小屏适配）

> 基线 v1.10.0（`6f6e271`）。本批来自《全功能检测与优化建议 v1.9》的 **C 批（中期）**，
> 按上一轮承诺**只做"语料基准 + 跨平台验收 + 小屏适配"，不扩大功能面**：
> 零新增运行时依赖、不改产品定位、PDF 表格/分栏等高成本项明确不做（理由见 §四）。
> 全量门禁：`pytest 2500+ passed` / `ruff 全绿` / `e2e 55/55` / `eval --profile base exit 0`。

## 二、怎么用（三条命令）

```bash
# 1) 语料体检（有敏感信息会 FAIL 并指出文件:行；报告中的号码已掩码）
python scripts/corpus_check.py <语料目录> --out corpus/report.md

# 2) 用真实语料跑发布门禁（E3/E5 成为硬门禁；E6 需要真实语料）
python scripts/eval_corrector.py --profile all --corpus <语料目录> --corpus-manifest corpus/manifest.json
# 有增强包的机器加 --require-packs：E4/E6 未真实运行即 FAIL

# 3) 在麒麟 ARM64 / Windows 真机产出验收报告（回传 json+md）
python scripts/accept_env.py                # 完整模式
python scripts/accept_env.py --fast --json  # 快速冒烟
```

## 三、这批的定位（重要）

- **C1 让"精度"从不可验证变成可验证**：以前的 E3 只有 224 汉字示意样本（1 处命中就是 44.6 处/万字，统计上无意义）；现在只要把脱敏语料放进 `doc/corpus/` 或外部目录，一条命令就能得到可复核的 E3/E5/E6 数字，并且语料本身的合规性（脱敏、规模、编码）先过体检。
- **C2 只解决"吞吐/召回可重复"，不冒充真实语料**：合成语料的价值是固定 seed 下可复现的 E5 吞吐与 E2 召回（注入错形→召回 99.4%），以及跨平台 sha256 比对；它**不能**用来声明真实公文上的误报率——这一点在 manifest、labels、每份文档文末三处都写了。
- **C3 解决"数据从哪来"**：本机 x64 的数字不能代表麒麟 ARM64。`accept_env.py` 把环境、字体、DPI、PDF 行距、备份恢复、纠错/提示耗时固化成一份可回传的报告，真机跑完发回来即可判定，无需开发者在场。
- **C4 用最小改动解决"打不开/超出屏幕"**：没有做响应式重构，只做"全局夹取 + 降低硬最小宽 + 一次性提示"，并明确最低分辨率口径。

## 四、明确不做（C 批边界）

| 项 | 为什么不做 |
|---|---|
| PDF 表格/分栏结构还原 | 成本高（版面分析）、收益不确定；B 批的段落聚合已解决"按行拆段"的主要痛点。需要时按真实样张单独立项 |
| 响应式布局重构 | 目标用户以办公 PC 为主；"夹取 + 最低声明"已覆盖 1024×640 需求，重构收益不足以承担回归风险 |
| 真实公文语料入库 | 语料含敏感信息，**由使用单位提供并本地保管**（`.gitignore` 已排除 `doc/corpus/*`，仅保留 README 与体检工具） |
| 人名启发式识别 | 正则猜人名误报率高（"张三李四"是常见测试词）；工具只做确定性检测，README 明写"没报错≠已脱敏，需人工复核" |
| eval `--corpus` 递归扫描 | 与 `corpus_check` 的递归口径不同：评测按"同目录一层"避免误把子目录的示例/说明当语料；README 已写明差异 |
