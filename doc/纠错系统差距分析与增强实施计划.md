## 〇、先说清楚三件事（口径声明）

1. **本文的"提案"指那份 8 周方案**。它的方向（分层、多模型协同、人机协同）与本项目
   **已经落地的架构一致**；差异主要在**工程约束下的选型**与**度量/闭环的缺失**上。
2. **本次实测语料不构成正式基准**。负样本缺省为 8 段公文体小样（224 汉字），
   外部语料可经 `--corpus` 注入。**所有"覆盖率"类结论在建立真实公文语料基准前都只能是量级判断**，
   这一点已写进 P0-1 的验收条件。
3. **本文只给方案，不改动既有纠错行为**。除新增 `scripts/eval_corrector.py` 与本文档外，
   未触碰任何业务代码；工作区内另一条线正在做的"重复字层"（`gwtool/core/repeat_rules.py`，
   未提交）被完整保留、未被修改。

## 二、现状盘点（以代码与实测为准）

### 2.1 实际流水线（五层 + 接入层）

```
文件/剪贴板 → 解析层（docx/doc/wps/txt/rtf/pdf/md/html + 扫描件 OCR 回退）
   → 分块（DocTree → 轻量块：heading/para/table，偏移块内局部化）
   → L1 精确词表（最长优先 + 首字分桶 + 负向上下文 + 书名号保护）
   → L2 上下文/标点/数字规则（同词不同境）
   → L3 词边界保护（jieba 边界 + 高频常用字序列抑制）＋ 重复字检测（同字连/间隔重复）
   → L4 神经精排【可选·增强包】MacBERT4CSC → ONNX
   → L5 语法纠错【可选·增强包】Mengzi-T5 Seq2Seq，G1–G10 门控
   → _dedupe（重叠去重·按置信度贪心）→ list[Correction]
   → 标记视图 / 逐处修正 / 整篇修正 / 保结构导出 DOCX·TXT / 忽略名单
```

## 四、关键缺陷清单（按证据强度排序）

### D1【P0·严重】L4 神经层在真实文本上误报灾难，且已作为正式包交付

- **现象**：在 6 句**人工确认无错**的公文句（191 汉字）上，开启 L4 后新增 **11 处**误报（57.6 处/千字），
  判分 **67 处/千字**（评测脚本口径，224 汉字）。更严重的是**改坏核心正确词**：
  `部署→谨骁`、`实→宝`、`将→射`、`情况→史史`、`会→伟`。
- **证据**：`scripts/eval_corrector.py` E6 项；独立探针 `--layers base,l4`；2606 字混排语料上 L4 新增 **938 条**。
- **根因（代码级）**：
  1. 增强包的"检测支路"是**合成的**：`build_csc_pack.py` 用 `pred != input` 造 `det`，
     等价于"模型不同意原字 = 有错"。而 MacBERT4CSC 在**未掩码位置**本就常给出不同预测 →
     **结构性过检测**，与领域无关。
  2. `csc_neural._decode_window` 有 4 条门控（词汇表/标点/等长单字/置信度钳制到 [0.55,0.95]），
     **但没有一条是"这个改动是否可信"的语义/混淆度闸门**——钳制后统一显示 0.90，反而掩盖了不确定性。
  3. `_run` 的窗口策略是"补 L1–L3 未覆盖的全部位置"，即**全量推理**，误报面积最大化。
- **影响**：用户一旦开启（设置页"一键勾选"），校对结果不可用，且**会把正确的"部署"改成乱码词**——
  对党政机关文本是灾难性错误。当前状态属"已交付但不可用"。
- **处置**：见 P0-2（误报闸门 + 默认关闭 + 标记为实验性）、P1-2（仅可疑片段推理）。
  **在闸门达标（E6 ≤ 0.3 处/千字）之前，不应再对外分发该增强包。**

### D2【P0·重要】生成层对"词典外新词"存在结构性盲区

- **现象**：混排/技术语域 14,076 汉字上误报 **18.47 处/万字**，其中"一键→一件"**独占 17/26 = 65%**。
- **根因（机理已定位）**：低置信（0.55）门控依赖两条保护，而"一键"**两条都不满足**——
  实测：`一键` **不在 CC-CEDICT 词典**（无法走"词典放行"）、`键` 的 jieba 词频仅 **804 < 5000`
  （无法触发"高频常用字序列抑制"）、`一键` 整体 jieba 词频仅 **3**（进严格门控后两端恰在词边界，放行）。
- **一般化结论**：**"新词/技术词/单位内部新提法"只要不在 1990 年代成书的 CC-CEDICT 里，
  就同时失去词典保护与常用字保护，成为生成层误报的靶子**。这类词在当代公文中越来越多（扫码、云端、平台化、一键、闭环…）。
- **影响**：约束了产品在"非严格公文体"文本（技术方案、汇报 PPT 文字、含附件的材料）上的可用性。
- **处置**：P0-3。

### D3【P0·中等】`_dedupe` 只看置信度，导致精标长对被 L2 短规则"截胡"，且造成 2 例漏报

- **现象**：精标对 `反应情况→反映情况`（conf **0.85**）被 L2 上下文规则 `反应(?=情况|问题|…)→反映`（conf **0.9**）覆盖，
  用户看到的提示从精确的"反应情况→反映情况"退化成"反应→反映"；而在 `反应人民群众的意见` 这类
  未入前瞻列表的搭配上 **0 命中（漏报）**。评测 E1 因此 **FAIL（99.4%）**。
- **根因**：`corrector._dedupe` 的排序键为 `(confidence, 覆盖长度)`，
  置信度是**主键**——于是"精度更低但置信度更高"的短命中会赢过长精标对。
- **影响**：①精标集无法达到宣称的 100%；②提示信息可读性下降；③E1 作为门禁永久红灯，掩盖后续回归。
- **处置**：P0-4。

### D4【P1】L5 语域敏感 + 速度不可交互

- **实测**：干净公文 6 句 → **0 命中**（表现良好 ✅）；混排语料 2606 字 → 35 处（`粘贴→贴文`、`词→字`、`段→断` 等明显误报）；
  **净耗时约 158 s / 2606 字 ≈ 60 s/千字**。G1–G10 门控在"整段丢弃"层面有效，但**段内单点错误无二次闸门**。
- **根因**：Seq2Seq 对含 ASCII/路径/markdown 标记的输入理解失稳；自回归贪心解码在 CPU 上无并行度。
- **处置**：P1-3（语域前置门控 + 异步深度检查入口）。

### D5【P0·根本】没有量化评测体系 → 所有"精度/覆盖率"结论都不可复核

只有两条孤立断言，且**口径互不一致**：`test_jianku_100_curated_pairs` 只测 100 条子集（故 README 的"100%"成立），
而全量 329 条实测 99.4%；"0 处/万字"在 284 字语料上测得，换语域即失真（18.47/万字）。
**没有任何一条门禁会把"开启增强层后的误报"纳入判定**——这正是 D1 能潜伏到"已交付"的原因。
- **处置**：P0-1（已交付工具）+ P1-5（补检测级/纠正级 F1 与真实语料基准）。

### D6【P0】缺反馈统计与阈值可调

忽略名单是唯一的反馈手段：**不落动作、不计数、不可导出、不可分析**；阈值散落在 6 处硬编码常量，
用户只能"全开/全关"。无法回答"哪些规则在真实使用中总被忽略"（= 应当下线的规则）。
- **处置**：P0-5、P1-1。

### D7【P1】专名（人名/机构名/内部术语）保护缺位

现仅"忽略名单"（人工逐个加）+ 52 条机构沿革。用户首次校对一份本单位文件时，
需逐个添加专名才能避免反复提示——**成本高到用户会直接关掉纠错**。
- **处置**：P1-4。

### D8【P1】纠错结果无留痕、与格式体检不联动

格式体检可导出规范 DOCX 报告（`core/report.py`），纠错却只能在界面看/导出修正稿。
党政机关需要"校对留痕"（谁、何时、改了哪些、依据什么）；且两个模块对同一份文件各跑一次，结论不合并。
- **处置**：P0-6、P1-6。

### D9【P1】数字/单位/日期规范规则仅 3 条

GB/T 15835 的"概数用汉字、计量用阿拉伯数字、年份不简写"等大量规则未覆盖，
而这一类的**改错成本极低、误报风险极低**，是性价比最高的规则扩张方向。

## 六、功能改进项清单

> 每项给出：目标 → 改法 → 落点 → 验收 → 风险。"落点"均为现有文件，不新建抽象层。

### P0（建议立即启动，1–2 周，零新增依赖）

#### P0-1 建立评测基线门禁 ✅ 本次已交付工具
- **目标**：把"精度"变成可复跑数值，并让 D1 这类整体性回归**必然红灯**。
- **改法**：`scripts/eval_corrector.py`（已交付，6 项判定 + JSON 落盘 + 退出码）。
  后续：①`--corpus` 指到真实公文语料；②在 CI 加一步 `--layers base`（**只跑基础三层**，
  保证 runner 无需增强包也能过）；③本地/有包机器跑全层。
- **验收**：CI 出现 1 条新步骤；E3 用真实语料时仍 PASS。
- **风险**：低。语料获取是唯一阻塞（见 §九）。

#### P0-2 L4 误报闸门 + 风险处置（**最高优先级**）
- **目标**：E6 从 67.0 → ≤ 0.3 处/千字。不达标就不分发。
- **改法（按性价比排序，建议全做）**：
  1. **混淆度闸门**（核心）：只在"原字 → 新字"**拼音相近或字形相近**时才接受。
     复用既有 `db/tokenize` 与 `dictionary` 表的 `pinyin` 列（**已有数据，零新依赖**）：
     拼音相同/声母韵母相近，或字形编辑距离 ≤ 1（可用五笔/结构近似表）。
     `部署→谨骁`、`实→宝` 这类**音形皆远**的替换会被一次拦掉。
  2. **检测阈值外置**：合成检测支路的 `det` 概率阈值从"argmax"改为**可配置阈值**（默认高），
     并把 `det` 概率**如实透出**到 `confidence`（不再钳成统一 0.90）。
  3. **上下文一致性**：替换后**整词必须仍为词典词或仍为合法搭配**，否则丢弃（"谨骁"不在词典 → 直接丢）。
  4. **默认关闭 + 显式实验性标识**：设置页文案改为"实验性功能，误报较多，建议逐条确认"，
    并在首次开启时弹一次确认（`ui/feature_dialogs.py` 的 `_on_pack_toggled`）。
- **落点**：`core/csc_neural.py`（`_decode_window` / `_run`）、`ui/feature_dialogs.py`。
- **验收**：E6 PASS；精标集与生成对召回**不下降**；新增单元测试用**假会话**注入
  "音形皆远"的替换，断言被丢弃（`tests/test_corrector_l4.py` 已有 `set_session_for_test` 钩子可复用）。
- **风险**：中。混淆度闸门会**降低真实召回**——须以 E4 同步监控，必要时只对"公文体"启用更严档。

#### P0-3 门控第 3 条：词典外新词保护
- **目标**：混排语域误报 → ≤ 2.0 处/万字（"一键→一件"类归零）。
- **改法**：在 `corrector._suppress_inside_common_words` 增加**新词白名单派生**：
  运行期从**用户资料库正文 + 导入文档语料**统计"高频出现的低置信命中词"，
  自动加入"放行集合"（例：某单位材料里"一键"出现 ≥3 次 → 自动放行）。
  派生结果缓存并随 `invalidate_cache()` 失效；**只对 conf < 0.7 的生成层命中生效，绝不触碰精标对**。
- **落点**：`core/corrector.py`、`db/dao.py`（新增只读统计查询）、`core/ruleset.py`（可导出查看）。
- **验收**：新增回归用例——"一键汇编"在**无资料库**时仍报（保持现状语义），
  在有语料支撑时**不报**；E3 语料重跑达标。
- **风险**：中。语料少时派生不出白名单；须设最小频次阈值（建议 ≥3 次且跨 ≥2 篇）。

#### P0-4 `_dedupe` 排序键修正 + 精标长对优先
- **目标**：E1 → 100%。
- **改法**：排序键由 `(confidence, 覆盖长度)` 改为 **`(覆盖长度, confidence, 是否精标)` 优先**，
  即"更精确的长命中优先"；对"精标对"给显式优先级位。同时对 L2 规则命中与 L1 精标对做
  **区间包含归并**：当规则命中是某个精标长对的子串时，丢弃规则命中。
- **落点**：`core/corrector.py::_dedupe`、`_check_regex_group`。
- **验收**：E1 = 100%；`反应情况` 提示应为"反应情况→反映情况"；既有 `test_overlapping_dedupe` 全绿；
  新增用例覆盖"短高置信 vs 长精标"冲突。
- **风险**：低，但**会改变用户可见提示文案**，需与 `ui/*` 的快照类测试核对。

#### P0-5 反馈统计闭环（把"忽略名单"升级为可度量闭环）
- **目标**：任何一次"采纳 / 忽略 / 手工改"都留下可统计的记录。
- **改法**：
  - 新增表 `correction_feedback(id, doc_hash, category, wrong, suggestion, action, conf, created_at)`，
    写进 `db/schema.py` 的 `TABLES`（全新库）与 `_MIGRATIONS`（老库补列/建表）；
    **不要动 `INDEXES`**（该文件已明确：索引统一在迁移后建）。
  - 在 `ui/correct_dialog.py` 的 `apply_selected / apply_all_blocks / ignore_selected`
    与 `ui/reference_panel.py` 的对应动作里落一条记录（**异常一律咽掉，绝不阻塞交互**）。
  - 新增"纠错统计"对话框：按类别/规则的采纳率、忽略率、Top 被忽略规则，**支持导出 CSV（UTF-8-BOM）**。
  - 与既有"忽略名单"打通：某规则被忽略率 > 阈值时给出"建议停用该规则"提示。
- **落点**：`db/schema.py`、`db/dao.py`、`ui/correct_dialog.py`、`ui/reference_panel.py`、`ui/feature_dialogs.py`。
- **验收**：新增测试——动作落库条数正确、CSV 表头与 BOM 正确、库异常时交互不受影响。
- **风险**：低。注意隐私：只存错词对与类别，**不存正文**（这一点必须写进注释与测试）。

#### P0-6 校对报告导出（校对留痕）
- **目标**：一次校对产出一份可归档、可转交拟稿人的规范 DOCX。
- **改法**：完全复用既有套路——把纠错结果组织成 `DocTree`（标题 + 结论摘要 + 明细表 + 修正后正文节），
  交给 `core/docxgen.generate_docx`，继承公文字体/行距/页边距与表格样式。**不要另起排版逻辑**。
  入口加在 `ui/correct_dialog.py`（`btn_docx` 旁新增"导出校对报告"）。
- **落点**：`core/report.py`（新增 `build_correction_report_tree` / `export_correction_report`）、`ui/correct_dialog.py`。
- **验收**：新增测试——报告 DOCX 可生成、含明细行数 = 命中数、中文字体不空白（复用 `test_pdf_cjk_font` 思路）。
- **风险**：低。

#### P0-7 重复字层合入主干

  + `e2e_check.py` 两条断言）尽快落主干并进 CI。
- **改法**：按既有流程提交，确认 `ruff check .`、785 用例、e2e 全绿。
- **风险**：低（代码已完备且有零误报实测）。**注意与并行会话的提交冲突**：提交前先 `git log` 核对，

### P1（3–4 周）

#### P1-1 校对档位（严格 / 平衡 / 宽松）——把散落常量收成一个策略对象
- **改法**：新增 `CorrectorPolicy`（dataclass，落 `core/corrector.py` 或独立小模块），
  承载 `low_conf / common_char_freq / 神经层是否启用 / 神经层混淆度门槛 / L5 是否启用 / 各层类别开关`；
  从 `settings` 表读写，设置页暴露三档预设 + 高级自定义。**默认仍为"严格"（现状行为）**。
- **验收**：三档各出一份 E3/E2 数值，写进 `eval` JSON；默认档与现状**逐字节一致**（回归保护）。
- **风险**：中。档位组合爆炸 → 用"预设 + 少量开关"而非全量自由参数。

#### P1-2 L4「仅可疑片段推理」+ 缓存 + 早停（采纳提案此处主张）
- **改法**：①**只对疑似区间推理**：以"未登录词 / 非常用字序列 / L2 规则邻近 / 词典 OOV 片段"
  构造候选窗口，替代当前的全量滑窗；②**窗口结果缓存**（段文本指纹 → 命中），重复段落零成本；
  ③**早停**：单段检测概率全低则跳过纠正支路。
- **验收**：E5/E6 达标的同时，L4 耗时 ≤ 3 s/千字；缓存命中率 > 30%（长文档场景）。
- **风险**：中。"仅可疑片段"会**降低召回**（可能漏掉 L1–L3 完全无感的位置）——与 E4 联调取平衡。

#### P1-3 L5 语域门控 + 异步深度检查
- **改法**：①**前置语域门控**：段落若含高比例 ASCII/数字/路径类字符（阈值可配），跳过 L5；
  ②**异步入口**：把 L5 从 `check_text` 的实时链路移出，改为用户显式点击"深度语法检查"后
  后台排队（复用 `ui/workers.py` 的 `FnWorker` + 进度 + 可取消）；
  ③结果只建议不自动改（保持现状语义）。
- **验收**：关掉 L5 后基础链路耗时回到 E5 水平；深度检查在 5000 字文档上不阻塞 UI。
- **风险**：中。**接口变更涉及 `corrector.check_text` 的调用方**，需先审计所有调用点。

#### P1-4 专名库（自动抽取 + 一键保护）
- **改法**：①从当前文档/资料库用 jieba 词性（`nr` 人名 / `nt` 机构）+ 机构后缀模式
  （"委员会/办公室/局/公司"）抽取候选专名；②呈现为"待确认专名列表"，用户勾选后进 `ignore_words`
  （或新建 `proper_nouns` 表带类型）；③校对时命中落在专名库内**一律放行**。
- **验收**：在真实公文上首轮抽取的专名命中率（人工核对）≥ 70%；放行后该类误报归零。
- **风险**：中。jieba 词性在无自定义词典时准确率有限 → 定位为"建议 + 人工确认"，不自动落库。

#### P1-5 检测级/纠正级双层指标（采纳提案 §六）
- **改法**：`scripts/eval_corrector.py` 增加 SIGHAN2015 格式数据集的加载与评分：
  **检测级**（错误位置是否找出）与**纠正级**（修正是否正确）分别报 P/R/F1，并按错误类型细分。
  数据来源与许可须登记（见 §十 合规红线）。
- **验收**：产出首份基线报告，并与上一版对比（回归门禁：F1 不得下降）。
- **风险**：中。数据集获取与许可证（SIGHAN 为学术用途）需确认。

#### P1-6 纠错 ↔ 格式体检联动
- **改法**：新增统一"文档合规报告"：一次体检同时跑格式检查与文字校对，
  合并为一份 DocTree 报告（`core/report.py` 扩展），复用 P0-6 的渲染路径。
- **风险**：低。

#### P1-7 数字/单位/日期规范规则扩容（GB/T 15835）
- **改法**：`corrector_data.NUMBER_RULES` 由 3 条扩到 20+ 条：年份不简写、概数用汉字、

- **验收**：新增规则不引入 E3 退化（这类规则误报极低）。

### P2（5–8 周）

#### P2-1 文内一致性校验（提案未覆盖，公文最痛）

- **验收**：在真实公文上人工核对，准确率 ≥ 80%（提示级，允许误报）。
- **风险**：中高。"不同写法"与"不同实体"的边界极易误判 → 一律提示级、绝不自动改。

#### P2-2 L4 体积与量化再评估
- **改法**：以 `--layers l4` 的 E6/E4 数值为准，重试三条路径：①fp16 ②per-channel QUInt8

  目标：包体 419 MB → ≤ 150 MB，且 E6 达标。
- **风险**：高（历史实验证明量化会毁图）；**触发条件**：若三条路径都失败，接受 fp16 体积，

#### P2-3 公文体领域自适应（无 GPU 路径）
- **改法**：不做继续预训练（无 GPU）。改为**语料驱动的规则挖掘**：
  ①从本单位历史公文高频搭配中挖"非常规搭配"作为候选规则；
  ②挖"同一概念的多种写法"喂给 P2-1；
  ③人工确认后入 `ruleset`（按来源成组管理，可停用/导出，机制已具备）。
- **验收**：候选规则人工采纳率 ≥ 30%（否则说明挖掘无效）。
- **风险**：中。需要语料与人工确认时间；**这是全案最依赖"真实公文语料"的一项**。

#### P2-4 麒麟 ARM64 分平台策略验证
- **改法**：在 ARM64 上实测 L4/L5 的耗时与内存，决定是否分平台默认关闭（CI 已有

## 十一、验收与门禁（本方案对工程纪律的增量）

**现有三道门禁**（保持不变）：`pytest tests/ -q` ｜ `ruff check .` ｜ `scripts/e2e_check.py`

**本方案新增四道**：

| 新增门禁 | 命令 | 阈值 | 何时跑 |
|---------|------|------|-------|
| ①评测基线（基础三层） | `scripts/eval_corrector.py --layers base` | E1 = 100%、E2 ≥ 75%、E3 ≤ 0.5 处/万字、E5 ≤ 100 ms/千字 | **CI 每次推送**（无需增强包） |
| ②神经层闸门 | `scripts/eval_corrector.py --layers base,l4,l5` | **E6 ≤ 0.3 处/千字**、E4 ≥ 60% | 有增强包的机器 / 发布前 |
| ③真实语料回归 | `--corpus <公文语料目录>` | E3 ≤ 0.5 处/万字 | 发布前（人工） |
| ④主包体积断言 | `scripts/smoke_dist.py` 增断言 | 主包体积不因纠错功能增长 | 打包后（CI） |

**e2e 自检建议新增步骤**：`重复字层零误报`（已由并行线加入）、
`精标集全量检出 100%`、`神经层误报闸门`、`反馈统计落库`、`校对报告导出`。

## 十二、待决策事项

1. **是否立即冻结 L4 增强包的分发**？在 P0-2 达标前，建议在设置页标为"实验性"并默认关闭；
   是否更进一步（从发布物中撤下该包）需你确认。
2. **真实公文语料能否提供**（含脱敏）？这决定 E3/E6 是"小样示意"还是"可发布门禁"，
   也决定 P2-3 能否启动。**这是全案第一优先的输入。**
3. **麒麟 ARM64 端是否接受"仅基础三层"**？若接受，ARM64 可不管 L4/L5；
   若不接受，P2-4 需增加 ARM64 实测与调优预算。
4. **是否授权引入 SIGHAN2015**（学术许可）用于双层指标？
   若不便，退化为"用本单位公文自建 500 句标注集"（需 3–5 人日标注）。
5. **P2-1 文内一致性校验是否列入本周期**？它是提案未提的差异化能力（公文最痛），
   但准确率门槛高、成本高，属"要不要做产品亮点"的取舍。
