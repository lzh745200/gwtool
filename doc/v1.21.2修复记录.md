# v1.21.2 修复记录（麒麟 Qt6 中文输入法）

> 基线 v1.21.1。这一版只处理一件事：**麒麟上切不出中文输入法**。
> 说明在前：本文的修复在 Windows 开发机上完成，**未在麒麟真机验证**；
> 真机验证步骤见 `doc/麒麟输入法排查与修复.md`，未通过验证前不要对外宣称已解决。

## 一、根因：Qt6 换成插件制，而系统的前端还是给 Qt5 的

Qt6 在 Linux 上不再默认走 XIM，中文输入必须有输入法框架提供的
`platforminputcontexts` 插件。而麒麟自带的 fcitx/ibus 前端是给 **Qt5** 用的，
本程序打包的是**独立的 Qt 6.11** —— 系统的 Qt5 插件对它完全无用。
系统若没装 fcitx 的 Qt6 前端，这座桥就是空的。

断点有四层，症状完全一样（窗口能开、英文能打、切不出中文）：
输入法框架没跑 / 没装 Qt6 前端 / 打包产物只搜包内插件 / Wayland 下 XIM 无效。

## 二、四处改动

### 2.1 不再盲信 `QT_IM_MODULE`（`gwtool/ui/ime.py`）

原实现看到 `QT_IM_MODULE` 有值就照单全收。**若该值指向的插件不存在，Qt 会加载失败，
一个输入上下文都没有** —— 比降级到 compose 更糟，等于把输入链路整条切断。
而 `scripts/gwtool.sh` 会按 `XMODIFIERS` 自动写 `QT_IM_MODULE=fcitx`，
于是在"没装 Qt6 前端"的麒麟上，程序会**必然**走进这条死路。

改为：先按插件清单校验；不可用则记 `invalid_request` 并进入降级链。

### 2.2 新增 XIM 兜底（同文件）

降级链变为四级：

| 顺序 | 条件 | 结果 |
|---|---|---|
| 1 | 用户显式设置的插件存在 | 用它（最佳） |
| 2 | 会话提示（XMODIFIERS/GTK_IM_MODULE）对应的插件存在 | 用它 |
| 3 | 有提示但插件缺失，且是 X11 会话 | `QT_IM_MODULE=xim`（不依赖任何 Qt 插件，能打中文） |
| 4 | 以上都不成立 | `compose`（只能拉丁字符）并给出可操作提示 |

XIM 由 fcitx/ibus 进程自己提供、Qt 的 xcb 平台插件内置支持，**不需要额外 .so**。
Wayland 下 XIM 不成立，诊断文本里会说明原因，并给出 `QT_QPA_PLATFORM=xcb` 的临时方案。

### 2.3 打包时显式收集输入法插件目录（`gwtool.spec`）

PyInstaller 的 PySide6 hook 各版本对 `platforminputcontexts/` 处理不一致 ——
实测 Windows 产物里只剩 `qtvirtualkeyboardplugin`。Linux 上若同样缺了
`libcomposeplatforminputcontextplugin.so`，上面降级链的最后一级也会落空。

改为只针对这一个子目录做确定性收集（两种 wheel 布局都探：
`PySide6/Qt/plugins/…` 与 `PySide6/plugins/…`），收集失败不阻断打包。

### 2.4 输入法可用时不再弹窗（`gwtool/app.py`）

加了 XIM 兜底后 `warnings` 非空，原逻辑每次启动都会弹「输入法可能不可用」——
输入明明能用还天天弹，是用噪音换修复。新增 `info["usable"]` 判定：
**不可用才弹窗 + 写日志；可用但降级只写日志**。

## 三、测试

`tests/test_ime_v121.py` 由 5 项扩到 10 项，新增覆盖：

- 显式设置且插件存在 → 保留；
- 显式设置但插件缺失 → 降级为 xim，并记录 `invalid_request`；
- 有输入法在跑但无插件 → 走 xim；
- Wayland 会话 → 不用 xim（落到 compose 并说明原因）；
- `xim` 本身没有插件文件，不得被误降级；
- `usable` 语义：compose 不算可用（能加载 ≠ 能打中文）。

其中原来那条"显式设置一律保留"的用例**本身就是缺陷的一部分**，已改写。

## 五、必须现场确认的五项

以下在 Windows 开发机上无法确认，已在 `doc/麒麟输入法排查与修复.md` 里标注：

1. 麒麟仓库里 Qt6 前端插件的确切包名；
2. Linux 产物是否真的带上了 compose 插件（需在 Linux 重新打包后查看产物）；
3. 系统插件与本程序 Qt 6.11 的 ABI 兼容性（靠 `QT_DEBUG_PLUGINS=1` 的加载日志）；
4. XIM 兜底在 UKUI 下的候选框位置；
5. Wayland 下 `QT_QPA_PLATFORM=xcb` 是否可用（需有 XWayland）。
