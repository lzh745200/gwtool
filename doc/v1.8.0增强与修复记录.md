## 二、校对能力

### 2.1 生成层精度闸门（修掉"把正确用词改成另一个词"）

`scripts/seed_data.py` 用同音/近音字**程序化配对**生成了 4 万条"错别字对"（confidence 0.55）。
它的结构性弱点是会把**合法的现代词**配成"错形"：

| 错形 | 被建议改成 | 后果 |
|------|-----------|------|
| 显式 | 显示 | "请显式传入"→"请显示传入"，语义变了 |
| 一键 | 一件 | "一键汇编"→"一件汇编" |
| 重试 | 重视 | "自动重试"→"自动重视" |
| 一版 | 一般 | "下一版"→"下一搬" |

真实语料实测这些占低置信命中的 **85%**。v1.8 加了**四道与分词无关**的闸门（只作用于
`confidence < 0.7` 的生成层命中，精标对/用户词条/规则层一律不受影响）：

1. **错形本身是已知合法词 → 不报**：判据取 jieba 词表 ∪ 随包 CC-CEDICT 词典 ∪ 用户术语。
   后者很关键——jieba 是 1990 年代口径，`一价`、`上疏`、`可恃` 这类现代/生僻词不在其中，
   但词典能兜住。属"同音异形真词"歧义，无模型不可判定；按红线「宁少报不误报」直接不报。
2. **命中是更长词典词的一部分 → 不报**：`一矢` 落在词典词 `一矢中的` 里，改它就是拆词
   （与 `repeat_rules` 的"更长词覆盖即放行"同源）。
3. **错形在同一文档内重复出现 ≥2 次 → 不报**：同一篇材料里反复出现的词形是作者的术语选择，不是笔误。
4. **人工精标错形永久豁免**（`_CURATED_WRONG`）：`布署`、`帐目` 这些被词典收录的
   真错别字照报；**逃生通道不变**：用户手动加进词库的词条置信度升到 0.99，不吃闸门。

**第二批（本轮续修）**：真实用户首启动即导入 `seed.db`，而种子库里带着 v1.7.x 时代的
**220 条精标快照**（`source='curated'`）。之前把这些快照也当数据加载，导致内置表的修订
在真实机器上**全部失效**：删掉的错对会"复活"（`行使权利→行使权力`、`哑巴→听障人士`），
降级的类别被旧值盖回（异形词又变回"错别字 0.85+"）。现在 `source='curated'` 的库内记录
一律跳过，**内置文件是唯一事实来源**（与 README「内置精标对始终生效、不受规则集开关影响」
的口径一致）。这条对用户可见：修复前后的真实安装不是同一套词库行为。

代价与收益：4 万条生成对里约 2.5% 不再参与召回（E2 约 -1.4pp，扫描器修复补回 1.0pp）；
真实语料低置信误报 **110 处 → 19 处**（3.37 → 0.52 处/万字）；词典全量探针里
"合法词被判错" **133 → 79 个**（余下全是本该报的变体/旧称/禁用词）。

### 2.1b 种子库产物重建（清理"遗留空表"）

随包 `seed.db` 是**旧 schema 时代的构建产物**：`PRAGMA user_version = 0`、只有 20 张表
（5 张业务空表 + 15 张 FTS 影子表），缺当前 schema 声明的 10 张表；同时带着 220 条
`source='curated'` 快照（即上一节那个"内置改了线上不变"陷阱的源头）。

本轮按当前 schema 重建（离线、只用文件内已有数据，不联网）：

| 项 | 重建前 | 重建后 |
|----|--------|--------|
| `user_version` | 0（旧库，会被当"待迁移"打开） | **7**（== `SCHEMA_VERSION`） |
| 表 | 20 张（缺 10 张当前表） | **40 张**（当前 20 张 + FTS5 影子表） |
| `error_pairs` | 40220（生成 40000 + curated 快照 220） | **39504**（只留生成对，按错形去重） |
| 同一错形多正形 | 496 个（建议哪条取决于库内行序） | **0**（取字典序最小，可复现） |
| 文件体积 | 15.7 MB | **12.6 MB**（VACUUM + 去重） |

配套四件事，防止以后再漂：
1. `scripts/seed_data.py` 同步改口径（不再写精标快照、按错形去重、写完设置
   `user_version` 并 VACUUM）——构建脚本与产物一致；
2. `corrector._load_patterns` 对"同置信度多正形"按正形字典序取小，
   用户导入词表产生重复时也给出确定性建议；
3. 新增门禁 `tests/test_seed_artifact.py`：产物必须 schema 同版本、无遗留/缺失表、
   无精标快照、错形唯一、词典完整 —— **下次改 schema 忘了重建 seed.db 会先红**；
4. U 层同口径：老用户库里仍残留的快照行不再出现在「纠错对 → 规则集」下拉里
   （`curated` 分组本来就开关无效），避免"停用这个分组能关掉精标对"的误导
   （`dict_manager._reload_rule_sets` + `test_dict_manager_hides_legacy_curated_ruleset`）。

### 2.1c 重复字层：跨词交界不再误判为间隔重复

真实语料回归抓到一处：审计报告里「**规则正则**写错会静默失效」被判为间隔重复
（`则正则→正则`，0.5 灰档）。根因是 cXc 通道只要求"删一字得真词"，没看这个词
是不是**跨越了正常短语交界**。修法与同字连 ⑤a 对齐：首个 c 是左邻词尾字、中间字
又是右邻词首字 → 放行。正例（是否是 / 在不在 / 了完了）只有一侧成词，不受影响。

### 2.2 规则数据扩容

| 表 | 变化 | 说明 |
|----|------|------|
| `CURATED_PAIRS` | 370 → **450** | 新增 80 条四字成语错形，逐条用 jieba 词频核验（错形 `freq ≤ 20`、正形 `freq > 0`、无跨词拼接来源） |
| `CONTEXT_RULES` | 49 → **50** | 新增 `权利(?=机构|机关)→权力`（方向唯一） |
| `NUMBER_RULES` | 6 → **21** | 百分数区间、百分之N、金额符号并用、全角千分位、日期分隔符/虚位、范围号、年份/时间范围、数字与单位空格、小数前导零、条款虚位、字母 O/l 误作数字 |
| 上下文规则召回 | 15 条增强 | 宾语前允许「了/的」与固定修饰语（`做出了决定`、`给与大力支持`、`发扬积极作用`、`渡过了艰难时期`、`签定了合同`…） |

全部数字规则是**提示级**（`ADVISORY_CATEGORIES`），批量写回/整篇应用整类排除，不会把正文改成标签。

### 2.3 文内一致性校验（新模块 `core/consistency.py`）

同一份材料里**同一实体两种写法并存**——这是词表法/规则法结构上看不到、而公文最容易被挑出的毛病：

* **数量**：`3个工作日` 与 `三个工作日`（先归一化数值，值不同不报）；
* **日期**：`2026年10月3日` 与 `2026.10.3`；年份简写与全写混用；
* **计量单位**：`公里/千米`、`公斤/千克`、`平方米/平米` 等法定与俗称混用；
* **机构名称**：同一文件里新旧机构名并存（查 `ORG_RENAME_PAIRS`，做"新称包含旧称"过滤）；
* **标点形式**：全角/半角同类标点混用（限定中文语境，遇英文括号/URL/时间/千分位不碰）。

纯函数、零依赖、幂等、10ms 级（2 万字实测 17.8ms），**只提示、不产生任何替换文本**，
接入写作提示层（scope「一致性」）。

### 2.4 校对报告导出（DOCX 留痕）

「任意文档纠错」新增「导出报告」按钮，产出一份可归档、可转交的规范 DOCX：

* 校对对象 / 时间 / 依据（`GB/T 9704` + 内置词库版本）；
* 结论摘要（按类别计数 + 按置信度三档：确认错误 ≥0.85 / 疑似 0.55–0.85 / 提示类）；
* 逐处明细表（序号/类别/原文/建议/置信度/依据）；
* 可选「修正后正文」节；
* 提示类条目的建议显式标注「提示类，建议人工确认」，避免读者误当替换文本。

排版复用既有 `docxgen` 公文模板，不另起一套。

## 三、写作能力

### 3.1 写作提示：4 类 → 16 项检查

新增：长句（>120 字）、逐段过长（>400 字）、句式疲劳（连续 3 句同字开头）、层次序号规范
（跳号/重号/倒序/层级颠倒）、标点密度（感叹号/问号/省略号过量）、口语化/网络化表达（33 词表）、
公文模糊表述（17 词 + 既有 `BAD_WORDS`）、同段重复短语、自称混用（我单位/本单位）、标题过长、
**文内写法不一致**（接一致性模块）。

红线不变：**只给建议、绝不改动正文**（模块内没有任何写入入口）；warn 只留给"骨架要素确实缺失"。
真实长文实测：20 篇文档 108 条提示、**0 条 warn**、平均 77ms/篇。

### 3.2 公文句式库：35 → 67 条

新增「请示·请求事项」「批复·答复意见」「纪要·议定事项」「通报·表扬与批评」「整改·措施与销号」
「函·商洽与答复」「部署·分工与节点」七组共 32 条，全部自撰通用表述、许可干净，并同步 `KIND_GROUPS`。

### P1（会把正确正文改坏）

| 编号 | 缺陷 | 修复 |
|------|------|------|
| P1-1 | 机构沿革表存在**自包含映射**（`旅游局→文化和旅游局`、`建设部→住房和城乡建设部`）：在**已正确的现行机构名**上再次命中，批量写回得到「市文化和文化和旅游局」 | 加载端丢弃"错形是正形子串"的映射（`_is_self_contained`）；旧称提示由一致性校验承担 |
| P1-2 | `行使权利→行使权力` 方向反了（权利=rights、权力=power），`股东行使权利` 会被改错 | 删除该精标对；反向（`权利机构→权力机构`）由方向唯一的上下文规则覆盖 |

### P2（能力缺口 / 潜在误报）

`以直报怨` 被改成"以直抱怨"；`窜改文件`（合法词）被改"篡改"；`侦察人员`（军事语境）被改"侦查"；

### P3（工程质量）

* 三处**恒真断言**（`... or n >= 0`、`session.calls >= 0`、`saved >= 0`）改为真契约断言；
* `test_parse_doc_via_com` 原来只断言最终文本，**COM 主路径失败靠降级链也能绿**：

## 六、已知边界（明确不修，附理由）

1. **词表外错字召回为 0**：词表法的结构性天花板，要靠可选增强包 L4/L5，主包不带模型（三条红线）。
2. **只出现一次的词表外新词**仍可能被同音生成对报到（约占实测残留的 1/3）：无模型不可判定；
   用户加一次词库即永久生效。
3. **汉字数字的不定指/序数义**（"一个量级" vs "1 个"）约每 2 万字 ≤1 条误提示，只是提示级。
4. **标点全半角类**面向 .docx/纯文本正文；喂 markdown/代码导出文本时行内代码里的半角冒号可能被提示。
5. **机构沿革**在历史引述语境（`1953年，卫生部`、`原卫生部`）已做豁免，但"引述旧机构名而未给年份"仍可能被提示。
