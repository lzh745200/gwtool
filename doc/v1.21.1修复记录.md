> v1.21.0 交付后，对工作树逐项复核，发现并修复 3 处**素材导入**真缺陷，
> 补全「我的素材」删除闭环；并按"统一收尾"要求做死代码审计清理、整理文档体系、

## 一、素材导入健壮性（真缺陷，3 处）

### 1.1 二进制文件被当文本吞进素材库
v1.21.0 起"未知扩展名按文本兜底"，本意是救 `*.通知` 这类无扩展名/奇怪扩展名的
纯文本；但 PNG/ZIP/DOC 等二进制也会走这条路，`utf-8 + errors=replace` 把它们
解码成一大串不可读字符并入库（标题还是文件名），污染"我的素材"。

修复（`gwtool/core/material_import.py`）：

- 新增 `_binary_reason(raw)`：前 4 KB 含空字节（`b"\x00"`），或解码后
  U+FFFD 与除 `\t\n\r` 外的 C0 控制符占比 > 10 %，判定为二进制；
- 命中时不入库，写进导入失败清单，原因文案为
  「疑似二进制文件（含空字节），不是文本类素材」/
  「疑似二进制文件（大量不可读字符），不是文本类素材」；
- 编码兜底统一走新增的 `_decode_any(raw)`：
  `utf-8-sig → utf-8 → gb18030 → utf-16 → big5 → utf-8(replace)`。

### 1.2 索引损坏时一次导入会清空用户素材列表（数据安全）
旧实现 `_load_index` 把"解析失败"当成空表返回，随后整份重写 —— 用户原有的
素材条目会被一次导入**静默覆盖清空**。

修复：`_load_index` 解析失败或结构异常时抛 `MaterialImportError`，本次导入
整体中止（提示「为避免覆盖原有记录，本次导入已中止…」），磁盘上的
`index.json` 一个字节都不改。

### 1.3 导入失败清单落盘异常被静默吞掉
`gwtool/ui/import_dialog.py` 里失败清单落盘的 `except Exception: pass` 改为
写日志（`ui.import` logger），导入流程不中断，但不再"无声无息"。

### 1.4 回归测试
`tests/test_material_import_v121.py` 新增 3 例：PNG/ZIP 被判为二进制且
`_load_index` 保持为空、无扩展名纯文本仍可入库、`index.json` 损坏时导入中止
且原文件字节不变。定向 `pytest tests/test_material_import_v121.py
tests/test_material_dialog_import_v121.py -q` → **13 passed**。

### 1.5 「我的素材」可以在界面里删掉了（补全导入闭环）
死代码审计发现 `material_import.remove_doc()` 全仓零引用 —— v1.21 的任意素材
导入只做了"进"、没做"出"：用户误导入一篇（或把二进制/整本无关文档拖进来）之后，
界面里没有任何入口删掉它，只能去数据目录手改 `index.json`。

修复（`gwtool/ui/material_dialog.py`）：

- 结果区新增「删除此素材」按钮：仅当**当前加载的是可写的「我的素材」包**
  且选中的是一条篇目命中时可用（公版语料包、模板命中一律禁用）；
- 删除前二次确认（`QMessageBox.question`，不确定则不删）；
- 删除后重载包并重跑检索；**删空时收起列表**并提示"可继续导入"——
  空包 `MaterialPack` 会按"缺少 index.json 或篇目为空"拒绝打开，旧实现会因此
  把已删除的旧命中留在列表里，这里显式处理；
- `tests/test_material_delete_v1211.py` 新增 2 例：可写包删除后索引清空、列表收敛；
  包被判定为只读时按钮禁用且删除请求不改索引。

## 二、代码清理（死代码审计）

- **审计方法**：AST 引用计数扫 `gwtool/**/*.py`（263 个文件、1689 个模块级符号），
  排除 `__all__` 成员、Qt 槽、pytest fixture、`__getattr__` 动态分发模块，以及
  字符串/文档命中；另跑 ruff `F` 全组 + `E7` 组补充规则。
- **删除 5 个实现残留**（零引用且已被取代/占位）：
  `material_import._read_text_fallback`（已由 `_decode_any` 取代）、
  `toolbox._CHUNK_SCALES` 与 `toolbox._HALF2FULL`（金额段位表与"兼容占位"，
  `amount_to_cn` 自带段位逻辑）、`repeat_rules._TOKEN_GUARD_DOC`（与函数
  docstring 重复的说明常量）、`dao._DICT_COLS`（SQL 已全部内联）。
- **保留 15 个"接口/数据面"符号**并说明理由，不做"为清零而清零"的删除：
  `style_data` 的 8 张参数表按
  [`archive/open-code-review审查报告.md`](archive/open-code-review审查报告.md) 第 25 条
  的既定决定保留（《公文风格量化指标与验收标准》逐表对照、属后续接线储备）；
  `theme` 的 `SHADOW`/`SECTION`/`MUTED_SMALL` 是 [`UI设计方案.md`](UI设计方案.md)
  记载的设计令牌；`APP_ID`/`PT_SIZE`/`DOC_NO_CLOSE` 属对外标识与数据面。
- ruff 补充扫描只报 2 处 `E731`（`gwtool/core/skeletons.py:80`、
  `scripts/e3_triage.py:238` 的 lambda 赋值）；`ruff.toml` 已含 `F` 全组与 `E9`
  并明确不开 `E7` 组，故不构成 CI 缺口。
- `scripts/` 无零引用文件；未删除任何被代码/脚本/测试按路径引用的文件。
- 清理临时分析脚本（`_zz_*.py`）—— 它们曾让
  `tests/test_packaging.py::test_no_hardcoded_build_machine_paths` 失败：
  该测试用 `ROOT.rglob` 扫**整个工作树**（不只 git 跟踪文件），脚本里写死的
  构建机仓库绝对路径（盘符 + 仓库名）会被判为"硬编码构建机路径"。

## 六、已知边界（沿用 v1.21.0，未变）

- 麒麟 V10 SP1（glibc 2.31）及以上可用；更老的 glibc 2.28 无 PySide6 aarch64
  轮子，程序会由 `--startup-report` 明确报出而非静默闪退。
- 只装 fcitx4（无 Qt6 前端）的系统需 `sudo apt install fcitx5-frontend-qt6` 或
  `ibus`；GitHub token 无 workflow scope，deb 的 `Recommends` 未由 CI 写入。
- 无麒麟真机环境，现场取证件 `gwtool.sh --startup-report` 与 `~/gwtool_启动诊断.log`。
- L4/L5 神经增强包仍为**可选、默认关闭**的实验特性，主包不带任何模型。
