## 2. 能力矩阵：自动替换 vs 仅提示

v1.14.0 起，"会写回正文的能力"与"只给建议的能力"有明确边界。判据是
`corrector.ADVISORY_CATEGORIES`（单一事实来源，UI/批量/报告全部从它取）。

### 2.1 自动替换（会真正改正文；「全部替换 / 批量写回 / 整篇应用」生效）

| 来源 | 规模 | 说明 |
|---|---:|---|
| 内置人工精标对 `CURATED_PAIRS` | **448** | `布署→部署`、`帐目→账目`…人工确认 |
| 上下文规则 `CONTEXT_RULES` | **49** | 截止/截至、做出/作出（收窄后）、签定/签订… |
| 标点规则 `PUNCT_RULES` | **11** | 标点重复、半角/全角归一（含 v1.10/v1.14 的书名号/引号/体裁/代码守卫） |
| 语法与表达 `grammar_rules` | 28 冗余 + 7 搭配 + 3 关联词 | `涉及到→涉及`、`加强力度→加大力度`… |
| 重复字（确认档） | 规则集 | 同字连 0.85/0.9（如 `进行行`、`部门门`） |

### 2.2 仅提示（**不写回正文**，可在列表里逐条手动应用）

| 来源 | 规模 | 原因 |
|---|---:|---|
| 数字用法 `NUMBER_RULES` | 21 | suggestion 是**提示标签**（"日期格式"），写回会把正文改成标签 |
| 表达提示 / 标点规范（grammar_rules） | 4 | 同上（跨词冗余/成对标点改法不唯一） |
| 机构沿革 `ORG_RENAME_PAIRS` | **51** | "时点判断"，历史引述里旧称是规范写法（v1.10 降级） |
| **生成层混淆对（seed.db generated）** | **39 504（conf 全 0.55）** | **本批降级**，见 §3.1 |

> 恢复生成层自动替换的**显式入口**（三选一，默认全部安全）：
> 1. `corrector.correct_block(text, apply_low_confidence=True)`（单次，代码显式）；
> 2. 删除 `corrector.ADVISORY_CATEGORIES` 里的 `"错别字(生成)"` 一行（全局）；
> 3. 不暴露给 UI —— 产品层默认不提供"一键替换 0.55 置信度建议"。
> 提示标签类（数字用法/表达提示/标点规范）**任何开关都不会放开**（写回即改坏正文）。

## 3. 逐类归因与修法（真实句子 → 归因 → 确定性守卫 → 正反例 → 复跑）

### 3.1 A 类：生成层整层降为提示级（26 处 / 26 处全是误报）

**真实句子（全部）**：`不怨天、不尤人`、`记者随侯指导员`、`每打一仗`、`最惨烈的一仗`、
`中国智造`、`AI智造`、`接过一旗`、`心头一震`（×2）、`红军有鞋穿`、`以术济世`、
`战友们围了过来`、`捡到了这张党员登记表`、`捡到篮子里就是菜`、`一击制胜`、
`渐成燎原之势`、`湘江之役`、`役前训练`、`将其视若珍宝`、`其视天下犹一家`、
`歇一歇`、`交融中渐成`、`万物之异`、`先禁其身`（×2）、`因俗而治`。

**归因**：错形本身就是**合法语素序列**（`一+量词`、`之+名词`、`其+动词`、`V+了`、
`有+名词`、术语 `役前/智造`），与 E2 的正样本同形。

**为什么不做形态守卫**（这是本批最重要的结论）：逐类实测了守卫的 E2 代价（800 样本）：

| 候选守卫 | 消掉的 A 类 | **E2 代价** |
|---|---:|---:|
| 首字 = 一 | 5 | **−11** |
| 首字 = 之/其 | 3 | −8 |
| 首字 = 以/因/随 | 3 | −6 |
| 首字 ∈ 中渐役捡先智尤 | 7 | −4 |
| 末字 = 了 | 1 | −1 |
| 首字/末字 组合全收 | 20+ | −26 以上 |

结论：**任何形态守卫都是拿召回换精度**，违反"E2 不得下降"的硬约束。且 lead 复核
seed 库确认 39 504 条 generated **confidence 全是 0.55**（不是"低置信子集"）。
故按红线「不静默自动替换」把**整层**降为提示级：命中照常列出、可逐条手动应用，
不进整篇/批量。**E1/E2 零代价**（E2 只统计"是否命中"，不看分类）。

**正反例**（`tests/test_real_corpus_fixes_v113.py::TestGeneratedLayerAdvisory`）：
* `correct_block("不怨天、不尤人；让人心头一震。")` → **原文不变**；
* `check_text` 仍报 `尤人→有人`（提示可见）；`report.ADVISORY_CATEGORIES` 含该类别；
* `correct_block(..., apply_low_confidence=True)` → 恢复替换（显式开关可用）；
* 精标 `布署→部署`、搭配 `加强力度→加大力度` 照旧写回。

### 3.2 B 类：重复字 4 处（`repeat_rules.py`）

| 命中 | 真实上下文 | 守卫（确定性） |
|---|---|---|
| `床床` | 一**床床**棉被 | ⑫ 量词叠用 `一+X+XX`：`床` 补进 `_QUANTIFIERS` |
| `把把` | 像一**把把**出鞘的刀 | 同上：`把` 补进量词表 |
| `亮亮` | 维和烈士申**亮亮** | ⑬b 叠词白名单（人名叠字；`亮亮` 本义明亮） |
| `嗅嗅` | 甚至想**嗅嗅**当年的油墨味 | ⑬c 动词重叠 VV：前一字 ∈ `想要去来试再多该应好` |
| `军军` | 十八**军军**长张国华 | ⑭ 词尾+词首相接：左 token 以连首字结尾（`十八`）、右 token 以连第二字起始（`军长`），两侧长度均 ≥2 |

（`岩岩` 同类：`龙舌岩` + `岩壁`，补进叠词白名单。）
**正反例**：`的的`/`是是`/`进行行`/`部门门`/`我我们` 仍报；`卿卿我我`/`小时了了` 不报。

### 3.3 C 类：关联词 3 处（`corrector._is_conjunction_enumeration_fp`）

真实句子：`“刁难”的目的只有一个，就是检验部队的极限` / `只有一个思想，就是…`。
归因：`只有` 是"仅仅有"（动词），`就是` 是判断句，不是"只有…才"的条件关联。
守卫：同分句 12 字内出现 **`只有 + 数量短语`**（一个/一种/一条/…）→ 不报。
正反例：`只有努力工作，就能成功` 仍报。

### 3.4 D 类：标点 5 处（2 真命中 + 3 体裁）

| 命中 | 判定 | 处理 |
|---|---|---|
| `办公厅,国务院`、`6200多平方米,全部` | **真命中**（源文本半角逗号） | 进白名单 `source_deviation`，不进 E3a |
| `(记者 李洋)`、`(采写：谌霖秋)` | 体裁（通讯社署名） | 括号内容以 记者/采写/摄影/本报/通讯员/编辑/来源/作者 开头，或含半角空格 → 跳过 |
| `？？`、`？？？`（引文内） | 体裁（文学强调） | `标点重复` 规则在引号/书名号内跳过；正文仍报 |

### 3.5 E 类：`起动→启动` 1 处（`corrector_data.py`）

真实句子：`我们建立【起|动|态】的“兵情档案”` —— `建立+起`（趋向补语）+ `动态`。
守卫：`(?<![机立设引兴崛发掀抓做打])起动(?!…|态)`。正例 `应按规程起动设备` 仍报。

## 4. 源文本偏差白名单（`--corpus-whitelist`）

真实语料里**源文本本身不规范**的地方会被引擎正确报出；若为了把 E3a 压到 0.5 而
收紧规则，就是把**正确能力**改坏。为此给 `eval_corrector.py` 增加白名单：

```bash
.venv/Scripts/python.exe scripts/eval_corrector.py --profile base \
    --corpus doc/corpus/real_all \
    --corpus-whitelist doc/corpus/白名单_源文本偏差_220篇.json \
    --json artifacts/eval_real220.json
```

* 白名单条目按 `(wrong, suggestion)` + 可选 `contains`（所在句片段）匹配，**不按文件/行**
  （语料会重新扁平化/去重）；
* 命中项从 E3a 扣除，JSON 单列 `E3a.source_deviation.{count,per_wan,items}`（逐条留档：
  错形、建议、类别、备注、上下文）；
* E3a 文本行会追加"源文本偏差（白名单剔除）N 处"；`e3_all` 总口径仍含它们；
* 本批白名单 2 条，均有原文出处（政府网原件确为半角逗号）。

## 5. 归因工具 `scripts/e3_triage.py`（本批新增）

```bash
# 跑一轮：类别/置信度/上下文（前后 25 字）/文件/建议 + 按类别聚合 + 人工判定栏
.venv/Scripts/python.exe scripts/e3_triage.py --corpus doc/corpus/real_all \
    --out artifacts/e3_triage_real220 \
    --whitelist doc/corpus/白名单_源文本偏差_220篇.json

# 人工复核后回写判定：{"verdicts": {"<id>": {"verdict": "误报", "note": "…"}}}
.venv/Scripts/python.exe scripts/e3_triage.py --corpus doc/corpus/real_all \
    --out artifacts/e3_triage_real220 --verdicts artifacts/e3_triage_real220.verdicts.json
```

* 口径与评测严格一致（同目录扫描、段 ≥8 汉字、E3a/E3b 分层、数据目录隔离播种）；
* 每条命中带稳定 `id`（文件+行+偏移+错形+建议的短哈希），`verdict`/`verdict_note` 默认空；
  `auto_hint`/`auto_reason` 只是预判，供复核时对照；
* 另出 `defects`（语料质量提示：成对符号不配对 / 页面元素残留 / 单段过长 / 疑似标题片段）
  与 `errors`（读取失败文件），**语料缺陷不计入引擎误报**。
