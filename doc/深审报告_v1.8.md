## 三 P1 缺陷（会把正确正文改坏 / 用户可见）

### P1-1 机构沿革条目自包含：批量写回把现行机构名叠加成病句

- **严重级**：P1（确定缺陷，用户点一次「全部替换」即产生病句）
- **位置**：`gwtool/core/corrector_data.py:434,435,436`（`旅游局→文化和旅游局`、`建设部→住房和城乡建设部`、`建设局→住房和城乡建设局`）；加载 `gwtool/core/corrector.py:93-97`；写回路径 `gwtool/core/corrector.py:492-505`（`correct_block` 默认只跳过 `ADVISORY_CATEGORIES`，其中**不含** `机构沿革`）；`gwtool/ui/reference_panel.py:66`（默认阈值 **0.5**）+ `:441`（只排除 advisory 类别）
- **根因**：三条配对的正形**包含**错形，而 `_check_exact` 是纯子串匹配，于是在**已经正确的现行机构名**上命中。
- **证据**（`probe_direction.py` / `probe_pipeline.py`，基线实测）：

```
[原文] 市文化和旅游局印发了实施方案。
  · 旅游局→文化和旅游局 [机构沿革] conf=0.70 span=(4,7)
  批量后: 市文化和文化和旅游局印发了实施方案。

[原文] 住房和城乡建设部发布通知。
  · 建设部→住房和城乡建设部 [机构沿革] conf=0.70 span=(5,8)
  批量后: 住房和城乡住房和城乡建设部发布通知。

[原文] 县住房和城乡建设局开展检查。
  apply_one: 县住房和城乡住房和城乡建设局开展检查。
```

同一路径在 `corrector.correct_block`（纠错面板「全部应用」走它）与 `reference_panel._apply_all`（默认 `置信度≥0.5`，0.70 会被纳入）都成立；实测 `correct_block` 输出：

```
市文化和旅游局印发方案。  ->  市文化和文化和旅游局印发方案。
住房和城乡建设部发布通知。 ->  住房和城乡住房和城乡建设部发布通知。
```

- **判定**：确定缺陷。另需注意 `gwtool/core/consistency.py`（v1.8 新增）也静态复用同一张表，修数据层会同时影响它。
- **最小修复建议**（按代价从低到高，建议 a+b 一起做）：
  1. **数据层**：删掉 `corrector_data.py:434-436` 这 3 条自包含条目（`旅游局/建设部/建设局`），但它们对应真实沿革提示，可改为在 `load` 阶段跳过"正形包含错形"的条目 —— 一行过滤：`if wrong in correct: continue`（在 `corrector.py:94` 的 for 循环内）。
  2. **通用护栏（推荐，价值更大）**：在 `_check_exact` 命中处加"已正确则跳过"判定 —— 若 `correct` 以 `hit` 为子串且 `text` 在命中位置已完整等于 `correct`，直接跳过：

     ```python
     # corrector.py 约 267 行 raw.append 之前
     if len(correct) > len(hit) and text.startswith(correct, i - correct.index(hit)):
         i += len(hit); continue
     ```

     这样任何"正形包含错形"的条目（含 v1.8 新增的同类）都不会再自伤。
  3. **可选**：把 `机构沿革` 加入 `corrector.ADVISORY_CATEGORIES`（它自己的注释就写着"提示级，建议核实后替换"），但**必须同时**确认 `batch.py / correct_dialog.py / report.py` 都从单一事实来源读取（目前它们确实都 import 该常量，改动面可控）。
- **归属冲突**：`corrector_data.py` 归 **impl-rules**（正在同文件追加 v1.8 段落，改 434-436 行会与他人 diff 冲突）；`corrector.py` 归 **impl-rules/lead**（工作树已改 73 行，含 `_suppress_inside_common_words` 重构）；`correct_dialog.py`/`report.py` 归 **impl-report**；`consistency.py` 归 **impl-consistency**。

### P1-2 「行使权利 → 行使权力」方向反了：把规范表述改成另一种含义

- **严重级**：P1（确定缺陷，语义级改错）
- **位置**：`gwtool/core/corrector_data.py:211`（`("行使权利", "行使权力", "易混词", 0.8)`）＋ `:488` 的负向上下文
- **根因**：`权利(rights)` 与 `权力(power)` 不是"错→对"，而是"两个都合法、看语境"。该条把**规范表述「行使权利」放在错形位**，只有前置词恰好是 `依法/合法/自由/正当/平等/民主` 时才被 `NEGATIVE_CONTEXTS` 救回；其余语境一律改错。v1.5.1 评审已发现并"修复"，但**只补了 6 个负向前缀，没有修方向**。
- **证据**（`probe_direction.py`，基线实测）：

```
[不应报] 公民依法行使权利，任何组织不得干预。        -> 无命中（负向生效）
[不应报] 股东行使权利的方式由章程规定。
   · 行使权利→行使权力 [易混词] conf=0.80
   批量后: 股东行使权力的方式由章程规定。      <-- 语义被改
[不应报] 党员必须正确行使权利、履行义务。
   批量后: 党员必须正确行使权力、履行义务。    <-- 语义被改
```

同一轮真实语料（`gwtool/**/*.py` 中文串）中该条命中 5 次，全部落在"合法写法"上（出现在说明文字的引号内，但说明它确实是高频触发点）。
- **判定**：确定缺陷（方向本身错；负向上下文是补丁不是修复）。
- **最小修复建议**：**删除 `corrector_data.py:211` 这一条**（保留 `:488` 键无害，可一并删）。召回由语境规则补：`权利(?=机构|机关) → 权力`（工作树 v1.8 已由 impl-rules 加入，本报告在基线副本上无法验证其行为，见九-不确定项）。若不想删，则必须改成**双向语境**：`行使权利` 只在后接 `机构/机关/部门` 等 power 宾语时才提示。
- **归属冲突**：同 P1-1（`corrector_data.py` = impl-rules）；`NEGATIVE_CONTEXTS` 的注释（`:485-487`）也需同步改，否则注释与数据不一致。

### P1-3 高置信两字精标对在"正常词边界"处命中，把正确词改坏

- **严重级**：P1（确定缺陷，默认阈值下会被批量写回）
- **位置**：`gwtool/core/corrector.py:336-337@d003b6b`

  ```python
  else:                                   # conf >= _LOW_CONF（人工精标）
      if boundaries and s not in boundaries and e not in boundaries:
          continue                        # 仅当"两端都在词内部"才抑制
  ```

- **根因**：门控方向不对称。低置信分支要求**两端都必须落在分词边界**（`both_ends`），高置信分支只要求"两端不能同时落在词内部"。于是「按装」在 `按|装机|容量` 里（左端是边界、右端在词内）**不被抑制**。
- **证据**（`probe_fp_cross.py`，基线实测；37 条构造语料命中 10 条，其中 7 条是纯误报）：

```

按排放标准执行。       · 按排→安排 [错别字] 0.96   批量后: 安排放标准执行。
按排列顺序摆放。       · 按排→安排 [错别字] 0.96   批量后: 安排列顺序摆放。
虽然烧了，但要及时报告。· 然烧→燃烧 [错别字] 0.95   批量后: 虽燃烧了，但要及时报告。
加强防害虫防治。       · 防害→妨害 [错别字] 0.96   批量后: 加强妨害虫防治。
必须品质过硬。         · 必须品→必需品 [错别字] 0.90 批量后: 必需品质过硬。
补给于前线。           · 给于→给予 [错别字] 0.95   批量后: 补给予前线。

```

（另 2 条「记帐目录」「这其间」属真错/规则本来就要报，不计入误报。）
`按排放标准` 在环保、统计类公文中是高频道词；`按装机容量` 在电力类公文中同理。**这两处误报的置信度是 0.98/0.96，高于任何 UI 的默认阈值**，用户「全部替换」必中。
- **判定**：确定缺陷（门控逻辑缺陷，而非数据问题）。
- **最小修复建议**：把 `corrector.py:336-337` 改成与低置信分支同构（对 `len(hit)==2` 的条目要求 `both_ends`）：

  ```python
      both_ends = s in boundaries and e in boundaries
      if not both_ends and len(hit) <= 2:
          continue        # 两字精标对必须整体落在词边界上
  ```

  注：v1.8 在途改动只重构了**低置信分支**（新增"错形是 jieba 词则不报""同文档重复≥2 不报"两道闸），**高置信分支原样保留**，所以本缺陷在 v1.8 中依然存在。修完须回归 `tests/test_corrector_probe.py`、`tests/test_corrector.py`、`tests/test_batch_correct.py`（其中 `按装` 是正向用例，必须仍然命中）。
- **归属冲突**：`corrector.py` 的 `_suppress_inside_common_words` 正被 **impl-rules/impl-core** 修改（工作树 diff 命中该函数）。

## 四 P2 缺陷（能力缺口 / 潜在误报）

### P2-2 「窜改文件」被改成「篡改文件」：窜改是合法词，改后语义从"改动"变"作伪"

- **位置**：`corrector_data.py:561-562`（`窜改(?=文件|数据|记录|账目|内容|历史) → 篡改`，conf 0.75，**不在 advisory 里 → 自动写回**）

- **最小修复**：把 lookahead 收窄为 `(?=数据|账目|历史)`，或直接改类别为 advisory。**不要**整条删（`窜改数据/历史` 仍是真错）。

### P2-3 「侦察人员」被改成「侦查人员」（军事/警务语境歧义）

### P2-4 「要求严紧」被改成「要求严谨」：严紧是《现汉》词

## 七 工程问题：全量 pytest 后 stderr 的 faulthandler 堆栈

### 7.1 复现（单文件即可稳定复现，无需全量）

```powershell
cd <repo>; $env:PYTHONIOENCODING='utf-8'; $env:QT_QPA_PLATFORM='offscreen'
```

### 7.2 归因（三条否证 + 一条确认）

| 假设 | 结论 | 证据 |
|---|---|---|
| pytest-timeout 的 dump | **否** | pytest-timeout 的 dump 头是 `+++ Timeout +++`/`Timeout (0:05:00)`；这里是 `Windows fatal exception: code 0x8007....`，且单文件 7 s 就跑完，远未到 `--timeout=300` |
| 残留线程 | **否** | 全部 7 处堆栈的 `Current thread` 都是**主线程**（同一 id `0x3e0c`），没有任何后台线程帧 |
| 残留进程 | **否** | 跑前跑后都只有 1 个 `wps.exe`（PID 12808，`10:32:13` 由 WPS 登录项 `aspcenter.dll --host` 启动），**没有**新残留；`Get-Process wps` 在跑完后无新增 |
| COM 调用的 RPC 首轮异常被 faulthandler 打印 | **是** | ① 代码 `0x800706be/0x800706ba` 正是 `RPC_S_CALL_FAILED` / `RPC_S_SERVER_UNAVAILABLE`；② 堆栈全部落在 `win32com.Dispatch / SaveAs2 / Close / Quit` 与 `_convert_via_com` 的释放点（`doc_parser.py:125` = `doc = app = None`，即 COM 引用释放引发 RPC 拆除）；③ 加 `GWTOOL_SKIP_COM_TESTS=1` 后 **fatal 计数 = 0**；④ Python 层无异常（测试通过、退出码 0），说明 RPC 错误被 COM/pywin32 自行接住，只是 faulthandler 的向量异常处理器把**首轮异常**也打印了出来（pytest 默认带 `faulthandler` 插件）。 |

### 7.3 是否会导致 CI 假红

- **不会**。单文件实测 `exit code = 0`、`21 passed`；GitHub Actions 步骤判红只看非零退出码，stderr 输出不影响。
- 另外 GitHub `windows-latest` **没有装 WPS/Word**，`Dispatch("kwps.Application")` 会抛 Python 级 `com_error`（Invalid class string），`real_doc` fixture 走 `pytest.skip` —— 该路径**不产生**上述 SEH dump（本地有 COM 才有）。此判断基于代码路径与注册表现状，**未在 CI 实测**（本轮禁止联网/不改 CI），标为推断。
- 风险点不在红绿，而在**误导**：任何人看到 "Windows fatal exception" 都会以为进程崩了，实际是噪声；而真正该被看见的问题（COM 主路径失败、测试靠降级链蒙对，见 **P3-8**）被噪声掩盖。

### 7.4 最小修复建议（不改代码也能止血）

1. **零改动**：CI 保持现状（不会红）；本地/文档注明"`.doc` COM 测试会打印 RPC 首轮异常，不影响结果"，或本地开发时 `GWTOOL_SKIP_COM_TESTS=1`（注意 P3-7 的退出码 5 副产物）。
2. **一行级改动**（`gwtool/core/parsers/doc_parser.py:112-125` 的 `finally`）：COM 释放顺序已是"先 doc.Close 再 app.Quit"，可再补 `pythoncom.CoInitialize()`/`CoUninitialize()` 成对包裹，并在 `app.Quit()` 后 `app = None` 之前 `import gc; gc.collect()`，把引用释放挪到异常可控范围内 —— **能减少但无法根除**（RPC 拆除发生在 `Release()` 内部，仍会触发首轮异常）。
3. **根治（推荐给 CI/本地脚本用）**：用 `-p no:faulthandler` 只包住 COM 隔离任务：例如 `python -m pytest tests/test_import_probe.py -p no:faulthandler`，或在 CI 加一个独立 job 专门跑 `test_*doc*.py / test_*genchain*.py`。代价是失去原生崩溃栈，故只对"已知会打 RPC 首轮异常"的文件生效，不要全局关。
4. **顺带修 P3-8**：在该测试里断言 `doc_parser._convert_via_com` 确实返回了目录，才能把 COM 主路径纳入门禁。

## 九 不确定项（明确标注，不猜）

1. **`哑巴 → 听障人士` 的权威依据**：新华社《新闻信息报道中的禁用词和慎用词》原文无法离线核验；本报告只能按语义判"哑≠听障"（疑似）。同理 `疯子/傻子` 的规范称谓是否应为"精神障碍患者/智力障碍人士"（更可能应为"精神障碍者/智力残疾人士"）也未核验。
2. **异形词身份**：`名符其实`、`流言飞语`、`不尽人意`、`挺而走险`、`座落`、`妥贴`、`狼籍` 是否为《第一批异形词整理表》/《现汉》认可的异形词，本机无权威词表可核（仓库 `third_party` 无此数据）→ 除 `妥贴/狼籍/图象/丰采` 判"确定异形词"外，其余标**疑似**。
3. **`疫情爆发 → 疫情暴发`**：规范用字确为"暴发"，但官方文本大量使用"爆发"；该条 conf 0.7 是否应保留，属产品取舍，本报告不判缺陷。
4. **`以致于 → 以至于`**：改法不唯一（可改"以致"），当前建议会轻微改变语气；判"疑似"。
5. **`行使权利/行使权力` 在法学语境的互换性**：本报告按通行规范判"行使权利"为正确形式；若产品面向法条引用场景，需法学顾问确认。
6. **faulthandler 在 CI（无 WPS/Word）是否出现**：按代码路径推断不会（会走 `pytest.skip`），未实测。
7. **v1.8 在途改动对本报告结论的影响**：`CURATED 370→450`、`CONTEXT 49→50`（新增 `权利(?=机构|机关)`）、`NUMBER 6→21`、低置信闸门新增两道，均**未验证**（不属于本次只读审计基线）。其中"权利语境规则"可能部分缓解 P1-2，"数字规则扩充"可能加重/缓解 P2-7、P2-9，需 impl-rules 自行复核。
