# UI 设计方案（v1：公文汇编助手）

> 面向落地开发的完整 UI 设计方案。基于当前代码实测（theme.py token 体系 /
> main_window 三栏骨架 / 23 处内联样式）制定，**不改动任何业务逻辑、信号槽、
> 数据契约**；所有改动收敛在样式层与既有 UI 组件内部。
> 配套阅读：《项目文件结构说明.md》第 10/12 章（改 X 去哪 / 红线清单）。

---

## 一、设计目标与现状评估

### 1.1 五个设计目标

| 目标 | 度量标准 |
|------|----------|
| 全局一致 | 100% 颜色/字号/间距取自 `theme.py` token，内联样式清零 |
| 一眼可辨 | 主操作（汇编/纠错/体检）在任意页面 1 次点击可达 |
| 反馈完整 | 每个耗时操作有进度；每个列表有空状态；每个失败有可执行文案 |
| 不破坏 | 1745 项测试全绿；模态框 mock 清单同步；麒麟/高分屏无回归 |
| 低成本演进 | 新增页面只需组合既有组件，不再手写样式 |

### 1.2 现状盘点（实测）

**已有的好底子**（保持并强化）：
- `ui/theme.py` 已是 token 化"精品浅色主题"：`PRIMARY #9E2B25` 公文红、
  `SURFACE` 纸面暖白、语义色五件套、字号五档、间距三档，`build_qss()` 全局生效；
- `ui/widgets.py` 有统一按钮行 `dialog_buttons()`（主按钮在右自动 default）、
  `info/warn/ask` 消息框封装、字体下拉（缺字 tooltip 提示，不污染模板值）；
- 主窗口三栏 QSplitter + 16 个内嵌 SVG 图标的工具栏动作 + 状态栏；
  最小 1024×640 且有"按可用屏幕收缩最小尺寸"的适配逻辑；
- `severity_color()` 让纠错红/橙/灰三级着色有单一来源；
- `ThreadSafeDialog` / `wait_for_threads` 保证后台任务退出安全。

**需要改进的问题**（按影响排序）：
1. **23 处内联 `setStyleSheet`**（feature_dialogs 20、correct_dialog 2、registry_dialog 1），
   颜色字面量散落，改主题必漏；部分写死在 token 体系之外的色值；
2. 缺少 **success（成功）** 语义色与"轻提示"通道——成功/次要在用 QMessageBox 打断，
   频次偏高的场景（如"已保存""已忽略 1 处"）缺非模态反馈；
3. **空状态无设计**：资料库为空、检索无结果、台账无数据时只有白板，新用户不知道下一步；
4. **加载中表达单一**：只有进度条；批量扫描/体检等阶段式任务缺"当前进行到哪一步"文案；
5. 工具栏 16 个动作平铺无分组，新用户建立"高频三件事"的心智成本高；
6. 状态栏信息密度高但无徽标视觉（督办逾期数只有文字）；
7. 无深色主题（Windows 强制浅色是刻意决定，但 token 化后深色是自然扩展）；
8. 高分屏（150%/200% 缩放）下边框发虚、图标模糊未系统校准。

### 1.3 硬边界（本方案承诺不触碰）

- 不改任何业务信号槽连接、dao 调用、worker 线程模型；
- 不改任何对话框的类名、方法名、返回值契约（`test_ui_actions_smoke` 等依赖）；
- 不引入新第三方依赖（无 qdarkstyle / qt-material，纯 QSS + 自绘）；
- 不动公文排版侧字体（`core/template.py` 的 FONT_* 是生成规范，与 UI 字体是两回事）；
- 新增任何 QMessageBox/QFileDialog 入口时，必须同步
  `test_ui_actions_smoke.py` 的 autouse mock 清单（挂死全量测试的头号事故源）。

## 二、设计原则

1. **公文红定调，纸面做底**：延续 `#9E2B25` 与暖白纸面色，让软件气质贴合"公文"而非"通用工具"；
2. **token 单一来源**：界面上的每个颜色/字号/间距都有名字，名字都在 `theme.py`；
3. **状态先于样式**：先定义加载/空/错误/禁用四态，再谈美观；
4. **文案可执行**：所有提示说清"发生了什么 + 下一步做什么"（与 `ui/errmsg.py` 风格一致）；
5. **渐进增强**：样式收敛（零风险）→ 组件补充（低风险）→ 布局优化（中风险），每期独立可回退。

## 三、整体布局结构

### 3.1 主窗口信息架构（保持三栏，明确分区职责）

```
┌────────────────────────────────────────────────────────────────┐
│ 菜单栏（5 组：文件/汇编/校对/台账/帮助）                          │ 36px
├────────────────────────────────────────────────────────────────┤
│ 工具栏【分组化】                                                 │ 44px
│ ┌高频区──────────┐┌材料区────────┐┌校对区────────┐┌台账与维护┐   │
│ │新建 导入 汇编★ ││模板 词典 对比││纠错 体检 朗读││发文 收文 备份│ │
│ └────────────────┘└──────────────┘└──────────────┘└───────────┘  │
├──────────┬──────────────────────────────────┬──────────────────┤
│ 左栏      │ 中栏（核心工作区）                │ 右栏              │
│ 资料库    │  编辑 / 预览 / 输出预览 三个标签页 │ 纠错结果 +        │
│ 260px    │  ────────────────────────────    │ 写作参考          │
│ 固定域    │  大纲树 40px 吸顶，正文占满       │ 300px 可折叠      │
│ 180–320  │                                  │                   │
├──────────┴──────────────────────────────────┴──────────────────┤
│ 状态栏：资料数 · 纠错库条数 · 【督办徽标】 · 数据目录 · 完全离线   │ 26px
└────────────────────────────────────────────────────────────────┘
```

调整点（均为布局参数，不动逻辑）：
- 左栏默认 260px（现约 240px 观感偏挤），允许收窄至 180px；右栏默认 300px，可一键折叠
  （折叠按钮放右栏顶部，图标 `chevron-right`，折叠态宽 12px 只留把手）；
- 工具栏按**使用频率分组**：高频区（新建/导入/汇编）主视觉，汇编用主色实底图标按钮；
  组间用现有 `QToolBar::separator` 分隔——纯 `insertSeparator` 层面调整；
- 中栏标签页沿用现有三页，仅在标签栏右端补一个"保存状态"指示（圆点：有未存改动）。

### 3.2 三档窗口密度（适配既有 1024×640 下限）

| 档位 | 触发条件 | 布局响应 |
|------|----------|----------|
| 紧凑档 | 宽 < 1180px | 左栏自动收窄至 200px；右栏默认折叠；工具栏只保留文字按钮不显图标 |
| 标准档 | 1180–1600px | 默认布局（260/弹性/300） |
| 宽屏档 | > 1600px | 左栏放宽至 320px；编辑区正文字号可开"演示模式"（+2pt） |

实现：`resizeEvent` 里按宽度切档，仅调 `QSplitter.setSizes()` 与工具栏
`setToolButtonStyle`——全部是既有控件的属性切换，无新建控件、无线程。

## 四、配色系统规范

### 4.1 Token 总表（在 theme.py 既有基础上**只增不改**）

既有 7 个色 token 全部保留原值（已实测协调）。新增以下 token 补齐语义缺口：

| Token（新增） | 值（浅色） | 用途 |
|---|---|---|
| `SUCCESS` | `#2E7D32` | 成功 / 已办结 / 体检通过 |
| `SUCCESS_BG` | `#E8F1E9` | 成功横幅底色 |
| `DANGER_BG` | `#F7E6E8` | 错误横幅 / 确认错误行底色 |
| `WARN_BG` | `#F7EFE0` | 警告横幅 / 疑似错误行底色 |
| `INFO_BG` | `#EEF0F2` | 提示横幅 / info 行底色 |
| `SELECTED_BG` | `#F5EAE7` | 列表/树选中行底（浅红纸，替代满行深红） |
| `HOVER_BG` | `#F5F2EC` | 列表悬停行底 |
| `DISABLED_FG` | `#A8A29A` | 禁用态文字（比 MUTED 更浅一档） |
| `FOCUS_RING` | `#9E2B254D` | 键盘焦点外圈（主色 30% 透明） |
| `SHADOW` | `#3A2E2847` | 卡片投影（沿用 PPT 设计语言） |

> 取值依据：SUCCESS 选用与公文红同饱和级别的深绿，避免"荧光感"；
> 三个 `*_BG` 与对应前景色成对设计，实测对比度 ≥ 4.5:1（正文 12pt）。

### 4.2 语义使用矩阵（防止滥用）

| 语义 | 只允许用于 |
|------|-----------|
| PRIMARY 红 | 主按钮、选中 tab 下划线、当前分类、必填星号、汇编主入口 |
| DANGER 红 | 确认错误（confidence ≥ 0.85）、删除类按钮 hover、逾期督办 |
| WARN 橙 | 疑似错误（0.55–0.85）、缺失字体提醒、容量告警 |
| SUCCESS 绿 | 办结状态、保存成功、体检通过结论、"无降级项" |
| MUTED 灰 | 次要文字、禁用态、info 级提示 |

规则：**一屏内主色面积 ≤ 10%**（公文文档本身留白多，红只做"笔"不做"纸"）；
纠错结果三级色沿用 `severity_color()`，本方案不改它的映射。

### 4.3 深色主题（二期预留，本期不实现）

- Windows 强制浅色是既有决定（`app.py`），**本期不动**；
- 因全部颜色已 token 化，深色主题 = 新增 `build_qss(dark=True)` 分支 +
  `config.py` 开关 + `main_window` 重启生效提示，工作量集中在一张色表上；
- 麒麟（Linux）侧桌面若为深色，跟随系统取 `QStyleHints.colorScheme`，默认仍浅色。

## 五、字体与字号规范

### 5.1 双轨制：UI 字体 ≠ 公文字体（红线）

| 轨道 | 用途 | 规范 |
|------|------|------|
| UI 字体 | 界面文字 | Windows：`"Microsoft YaHei"`（既有）；麒麟：`"Noto Sans CJK SC", "WenQuanYi Zen Hei", "Microsoft YaHei"` 回退栈 |
| 公文字体 | 生成 docx/PDF | 永远取自 `core/template.py` 的 FONT_*（方正小标宋/仿宋/…），缺失只提示不替换 |

**任何界面样式不得反向写入模板**（既有教训：字体下拉的显示文本被写进模板会污染 docx，
`make_font_combo` 已用 tooltip 规避，保持）。

### 5.2 字号阶梯（沿用现有五档，补行高）

| Token | pt | 行高 | 用途 |
|-------|----|------|------|
| TITLE | 16 | 1.3 | 对话框标题、向导步骤标题 |
| SECTION | 13 | 1.35 | 分组标题、面板小标题 |
| BODY | 12 | 1.45 | 正文、按钮、输入框、表格 |
| SMALL | 11 | 1.4 | 状态栏、辅助说明、表格次要列 |
| MUTED_SMALL | 10.5 | 1.4 | 占位文字、来源标注 |

规则：一个屏幕内最多出现 **3 档**字号；加粗只用于标题与主按钮（正文不加粗）；
编辑器正文区字号独立（用户可调，默认随模板），不受 BODY 约束。

### 5.3 间距系统（既有三档 + 两个用途说明）

`MARGIN 12 / GROUP_GAP 8 / ROW_GAP 4`（px）。补充使用细则：
- 对话框外边距一律 MARGIN；分组之间 GROUP_GAP；表单行内 ROW_GAP；
- 按钮内边距沿用 QSS 的 `4px 14px`；表格单元格 `4px 6px`；
- 弹窗最小宽 480px、最大不超屏宽 − 80px（沿用 `feature_dialogs` 的 `fit_dialog` 逻辑）。

## 六、核心页面视觉规格

### 6.1 主窗口（QMainWindow）

- 背景 `BG` 纯白；三栏之间用 3px `BORDER` 分隔线（既有 Splitter 样式）；
- 工具栏背景 `HEADING_BG`，分组分隔线；**汇编按钮**用主色实底 + 白字 +
  圆角 3px（QSS `QPushButton:default` 既有样式，直接复用）；
- 状态栏 `SURFACE` 底，督办逾期徽标：圆角胶囊 `DANGER` 底白字，数字 > 0 才显示；
- 窗口标题保持 `公文汇编助手 vX.Y.Z（单机离线版）`（用户可辨识版本）。

### 6.2 编辑器页（editor_panel）

- 大纲树：宽 200px 吸左，`SURFACE` 底无边框，当前节 `SELECTED_BG`；
- 正文编辑区：`BG` 白底、无边框（去 QPlainTextEdit 描边），行距 1.5；
- 查找条：顶部滑入式（现有 QFindBox 形态保持），命中计数用 `MUTED_SMALL`；
- 自动快照提示：保存后状态栏右侧闪现 `SUCCESS` 圆点 2 秒（非模态，不弹窗）。

### 6.3 资料库（library_panel）

- 检索框：圆角 6px、`SURFACE` 底、左侧放大镜图标、Esc 一键清空；
- 分类树：当前节点 `SELECTED_BG` + 主色左侧 3px 指示条；计数用 `MUTED_SMALL` 右对齐；
- 文档列表行高 32px：标题 1 行省略 + 副行（字数/时间）`SMALL` `MUTED`；
  悬停 `HOVER_BG`，多选计数显示在列表底部工具行。

### 6.4 参考面板（reference_panel）

- 纠错结果区：每条命中 = 色条(3px, 按 severity) + 原文/建议双列 + 操作按钮组
  （替换/忽略）；整行底色按 `severity_color` 对应 `*_BG`；
- 写作参考区：段落粒度卡片化——卡片 `SURFACE` 圆角 4px，含来源徽标
  （资料/词典/句式/草稿）+ 正文摘要 + "溯源/插入"两个次级按钮；
- 两区之间的 Splitter 保持纵向拖拽，折叠把手上加"结果 N 条"计数。

### 6.5 一键汇编向导（compile_wizard，三步）

- 步骤指示器：顶部横向三节点（选材料 → 定模板 → 出成品），
  当前节点主色实心、完成节点主色描边对勾、未达节点 `BORDER` 灰；
- 第 1 步材料列表：拖拽把手 + 勾选框 + 标题 + 格式徽标（docx/pdf/扫描）；
  解析失败的材料用 `WARN_BG` 行底 + 原因文案（对齐 compiler 修复后的 failures 呈现）；
- 第 2 步模板：左侧模板列表、中间参数表单、右侧**实时预览缩略**（既有）；
- 第 3 步输出：勾选 docx/PDF/小册子；完成后成功横幅（`SUCCESS_BG`）+
  产物路径逐条列出（可点击打开目录），来源清单勾选项保持默认勾选。

### 6.6 台账页（registry / receive）

- 工具行：筛选下拉组（年度/机关/文种/状态）+ 搜索框 + 导出按钮，右对齐统计摘要；
- 表格：表头 `HEADING_BG`（既有）、斑马纹 `SURFACE`（既有）、行高 30px；
  状态列用胶囊徽标（在办=主色描边、办结=`SUCCESS_BG`、归档=`INFO_BG`）；
- 逾期行：`DANGER_BG` 底 + 到期日加粗红字（与督办提醒同一判据 `reminder.py`）。

### 6.7 体检/纠错对话框（correct_dialog / feature_dialogs）

- 结论横幅：顶部全宽（`*_BG` 底 + 前景色），图 24px + 结论一句话 + 统计徽标；
- 结果列表同 6.4；导出按钮在有结果时才可用（既有 `_has_result` 纪律保持）；
- 20 处内联样式全部收敛到 token（见 11.1 P0 期清单）。

### 6.8 设置类对话框（词典管理/备份/系统与安全）

- 左侧分类导航（词典管理已有四标签，改为列表式导航可选，二期）；
- 危险区（恢复备份/清空回收站）：独立分组 + `DANGER` 描边 + 二次确认
  （沿用 `ask()`，确认按钮文字写明后果，如"恢复并覆盖当前资料"）；
- 所有开关统一 QCheckBox 行式（左说明右开关），不再混用按钮当开关。

## 七、关键组件规范

### 7.1 按钮（五态 + 层级）

| 层级 | 样式 | 用途 |
|------|------|------|
| 主要 | 主色实底白字，hover `PRIMARY_DIM` | 每对话框最多 1 个（`dialog_buttons` 已自动管理 default） |
| 次要 | 白底 `BORDER` 边框，hover 主色边 | 常规操作 |
| 危险 | 白底 `DANGER` 边框+文字，hover `DANGER` 实底 | 删除/恢复/清空 |
| 幽灵 | 无边框文字钮，hover `HOVER_BG` | 行内操作（替换/忽略/溯源） |
| 图标 | 32×32 工具栏钮，SVG 线性图标 `ICON` 色 | 工具栏 |

五态齐备：normal / hover / pressed(`HEADING_BG`) / disabled(`DISABLED_FG`) /
focus(1px `FOCUS_RING` 外圈 + 键盘可达)。

### 7.2 表格与树

- 选中行：`SELECTED_BG` 底 + 主色文字（放弃"满行深红+白字"，长列表更柔和）；
- 斑马纹保留；列宽策略：首列拉伸、次列 `ResizeToContents`；
- 空表格显示内嵌空状态（见 7.6），不弹窗。

### 7.3 表单

- 必填：标签前主色星号；校验失败：输入框 `DANGER` 边框 + 行尾 `SMALL` 红字说明；
- 输入框统一圆角 3px、focus 主色边（既有 QSS）；数字输入带单位后缀
  （`make_mm_spin` 的 mm 规范扩展到页数/份数/天数）。

### 7.4 徽标与标签（chip）

- 胶囊形（圆角 = 高度/2）、12px 高 20px 内边距 6px；
- 三类：状态徽标（在办/办结/归档）、格式徽标（docx/pdf/扫描）、计数徽标
  （纠错 N 处/督办 N 件逾期）。全部用语义 `*_BG + 前景色`，禁用新造色值。

### 7.5 进度与加载

| 场景 | 控件 | 文案模式 |
|------|------|----------|
| 确定性（批量 N 件） | QProgressBar + 百分比 | "正在扫描 12/200 篇…" |
| 不确定（转换/渲染） | 忙碌指示（进度条 range 0,0 既有） | "正在生成 PDF…" |
| 阶段式（体检/导入） | 进度条 + 阶段文案（`_tick` 回调已有，接上即可） | "第 2/4 步：解析 PDF…" |

取消：所有可取消 worker 的对话框保留"取消"按钮（协作式 stop 已实现），
取消后显示"已取消，未保存任何更改"或"已取消，已完成部分保留"（按任务语义二选一，写死在任务内）。

### 7.6 空状态组件（新增 `EmptyState`，P1 期）

统一组件：图标(48px 线性) + 一句话 + 行动按钮（可选）。
```
📭  资料库还是空的
    拖入 docx / pdf / txt，或点击"导入材料"
    [ 导入材料 ]   [ 剪贴板入库 ]
```
必做五个位置：资料库列表、检索无结果（行动=清空条件）、纠错结果
（行动=重新检查）、台账表格、回收站。实现为纯 QWidget 组合，不引资源文件，
图标复用 `icons.py` 线性风格。

### 7.7 反馈通道分级（新增，P1 期）

| 级别 | 通道 | 适用 |
|------|------|------|
| 轻提示 | 状态栏内嵌消息条（`SUCCESS`/`INFO` 底，4 秒自清） | 已保存/已忽略/已复制 |
| 确认框 | `ask()`（既有） | 危险/不可逆操作 |
| 错误对话框 | `warn()`（既有） | 操作失败，必须逐字读 |
| 横幅 | 对话框顶部全宽 `*_BG` | 任务结果汇总（纠错 N 处/体检通过） |

原则：**能用轻提示就不用弹窗**；同一会话同类轻提示合并（"已忽略 3 处"不刷 3 条）。

## 八、交互流程与状态反馈（关键路径走查）

### 8.1 导入材料（最高频）

拖入文件 → 对话框列出待导入清单（格式徽标 + 大小）→ 后台解析（进度条 +
阶段文案）→ 完成横幅："成功 8 篇 · 重复跳过 1 篇 · 失败 1 篇（附原因）"
—— 失败行可点开看原因（对接 `errmsg.friendly_parse_error`），**绝不静默**。

### 8.2 一键汇编

第 3 步点"开始"→ 按钮立即禁用 + 忙碌指示（既有防重入纪律：
`setEnabled(False)` 必须先于一切确认框）→ 完成后产物卡片逐条列出
（打开目录/登记台账两个动作）→ 字体缺失时追加 `WARN` 提示行（`missing_note()` 既有）。

### 8.3 纠错

按 F7 → 右栏显示进度与阶段 → 结果按置信度三色呈现 →
"全部替换"前必须二次确认（列出将改动 N 处、排除提示类 N 处——
`ADVISORY_CATEGORIES` 既有语义原样展示）→ 完成轻提示"已替换 N 处，Ctrl+Z 可撤销"。

### 8.4 体检

运行中显示阶段（已有 `_tick`）；完成后结论横幅
（通过=绿 / N 项建议=橙 / N 项错误=红）→ 导出按钮仅在有结果时可用（既有）。

### 8.5 错误提示文案规范（对齐 errmsg.py 风格）

三段式：**发生了什么 + 为什么 + 下一步**。
反例："错误：Error 32"。正例："备份未完成：数据库正被「后台导入」任务占用。
请等该任务结束后重试，或先在对应窗口停止它。"
禁止：裸异常类名、英文堆栈、"操作失败"无下文。

### 8.6 状态总表（每个列表/任务页必须四态齐备）

| 状态 | 表现 |
|------|------|
| 加载中 | 进度/忙碌指示 + 阶段文案；入口按钮禁用 |
| 空状态 | `EmptyState` 组件（含下一步动作） |
| 错误 | 对话框或横幅 + 可执行文案；输入保留，不清空用户已填内容 |
| 成功 | 轻提示或结果横幅；产物可直达 |

## 九、桌面端与小屏/移动场景适配策略

### 9.1 诚实定位

本项目是**桌面离线单机应用**（Windows x64 + 麒麟 ARM64），不存在移动 App。
"移动端适配"在本项目中落实为四件事，全部不触碰业务层：

1. **小窗口三档密度**（见 3.2）：1024×640 下限内完整可用（工具栏文字化、右栏折叠、
   左栏收窄）——现有 `fit_to_screen` 逻辑扩展为三档判断；
2. **高分屏（125%–200% 缩放）校准**：图标统一 2x 导出（SVG 本身矢量，校准渲染
   `Qt.AA_UseHighDpiPixmaps` 类既有开关）；边框 1px 在 150% 下改 1.5 整数化，
   避免发虚；对话框 `fit_dialog` 已按屏幕裁剪，保持；
3. **触屏笔记本**：所有可点目标 ≥ 32px（行高 30px + 内边距已达标），
   工具栏按钮 44px 命中区；不引入手势（成本高收益低，明确不做）；
4. **便携 U 盘场景**（`--portable`）：无新增要求，但设计上保证零动画依赖
   （低端核显不卡），QSS 不用 transition/animation。

### 9.2 若未来做移动/网页端（路线预留，本期不实施）

当前设计的 token 化与组件化（EmptyState/徽标/横幅/四态）与 Web 端可一一映射；
业务层（core/db）本就与 UI 解耦，届时新增 Web 前端调用同一套逻辑即可，
**本方案不为移动端提前做任何妥协**（如超大触控按钮），避免伤害桌面主场景。

## 十、可访问性与质量红线

- 对比度：正文 ≥ 4.5:1，辅助文字 ≥ 3:1（新增 token 已按此取值，落地时抽查）；
- 键盘：Tab 顺序 = 视觉顺序；所有对话框有默认按钮（Enter）与 Esc 取消（Qt 默认）；
  主快捷键保持：F7 纠错、Ctrl+F 查找、Ctrl+S 保存（既有）；
- 焦点可见：QSS 统一 `FOCUS_RING`，禁止 `outline: none` 出现在可交互控件
  （现有列表 QSS 有 `outline: none`，P0 期替换为焦点底色方案）；
- 不用纯颜色表意：错误行必带图标或文字（色弱用户）；
- 字号缩放：跟随系统 DPI，不提供"界面字体大小"设置（避免布局破碎，
  编辑区字号已有独立调节）。
